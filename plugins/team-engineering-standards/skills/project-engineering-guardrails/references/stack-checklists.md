# 技术栈检查清单

只使用目标项目实际采用的部分。项目规范可以收紧这些要求。

## Vue / TypeScript

- 启用 TypeScript 严格模式，避免用 `any`、非空断言或重复类型绕过建模问题。
- 目录按 API、组件、布局、页面地址、状态、工具和视图划分；业务页面内部可继续按组件、组合函数、表单和类型拆分。
- API 客户端集中处理基础地址、认证、超时和错误转换；页面不得散落请求细节或秘密信息。
- 每个异步区域必须定义加载、空、失败、无权限和成功状态。
- 页面访问检查与服务端授权分工明确；前端隐藏入口不能替代后端身份和权限检查。
- 组件和导出内容必须用注释说明职责和使用限制，禁止用注释逐字复述代码。
- 自动检查至少覆盖类型检查、生产构建、自动测试，以及项目规定的注释和接口规范检查。
- UI 验收必须覆盖目标视口、溢出、缩放、键盘、焦点、对比度、真实状态和正式页面内容。

## Java / Spring / MyBatis

- 包结构表达职责；Controller 只处理请求协议与校验，Service 承担业务与事务，Mapper 只负责数据库读写。
- DTO（接口输入对象）、VO（接口输出对象）、内部模型和数据库读写模型用途明确，不用一个对象贯穿所有层。
- 新增或修改的公共类型和方法具有准确 Javadoc，并随行为变化同步更新。
- 事务由业务服务控制；明确如何保证重复提交不会产生重复结果，并说明并发、超时、重试和错误转换规则。
- MyBatis SQL 参数化，动态 SQL 有边界测试，不拼接不可信输入。
- 日志不记录凭证、完整患者数据或其他敏感字段；审计与运行日志职责分离。
- 自动检查至少覆盖编译、静态规则、单元测试、集成测试和依赖约束。

## SQL Server

- 先确认服务器版本和数据库兼容级别，再使用语法、索引和驱动特性。
- 一个业务变更维护一个可追溯主版本；共享环境后的补丁引用主版本并连续编号。
- 数据库定义语句（DDL）、约束、索引、默认值、时间规则和数据库注释必须与业务含义一致。
- 脚本具备明确前置条件、事务策略、失败行为和回滚/恢复说明。
- 生产数据变更先评估锁、日志增长、执行窗口、备份与恢复，不以开发库速度推断生产风险。
- 数据库变更自动检查覆盖命名、版本关系、兼容性禁用项和必需注释；关键变更仍需在目标版本数据库演练。

## Web UI 验收

- 先建立页面、弹窗、抽屉、表格、表单和关键状态的区域清单。
- 以风险决定检查深度，至少检查目标桌面视口、内容密度、固定区域、滚动和遮挡。
- 验收截图必须对应实际构建和真实页面状态；原型、占位数据和调试标识不得冒充正式结果。
- 修复后定向复验受影响区域，并执行一次关键路径回归。
