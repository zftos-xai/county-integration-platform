# Mobile responsive H5

Use for responsive Web pages in mobile browsers. Read the destination project's supported surfaces, viewport matrix, design rules, API/flow contract, and test guidance first. Record CSS viewport and any browser device-emulation method. Choose supported representative widths and breakpoint risks; do not invent a universal support range.

Check, where relevant:

- first-screen purpose and information order;
- reachability of primary actions and project-defined touch target requirements;
- fixed navigation/actions in relation to system safe areas;
- full-page scrolling, horizontal overflow, sticky content, dialogs, drawers, and ownership of nested scrolling;
- keyboard-open behavior, focused field visibility, submit/cancel reachability, and validation recovery;
- long text, identifiers, empty/zero values, and content stress without loss of essential actions;
- loading, empty, failure, unauthorized, retry, and session-expiry states from the product contract.

Browser emulation supports conclusions only for the recorded local browser scope. It does not prove a physical phone, real touch, native WebView, operating-system keyboard, or device certification.
