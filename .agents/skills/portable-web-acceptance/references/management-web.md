# Management and operations Web

Use for browser-based administrative, operational, and configuration workbenches. Read the destination project's role/permission matrix, supported surfaces, routes, business lifecycle, API contract, UI standards, and test guidance first.

Check, where relevant:

- target object, tenant/organization context, selected scope, and impact of single or bulk actions;
- search, filters, sorting, pagination, selection, list/detail relationship, dense content, and narrow-window behavior;
- draft, saved, active, disabled, approved, rollback, or other real lifecycle states;
- server-side permission denial as well as client-visible controls, and audit behavior required by the project;
- long forms and overlays at short viewports, focus order, field errors, input retention after failure, cancel and recovery;
- true empty/no-result/unconfigured/no-permission/request-failure states and whether data is API-backed or mock.

Use only the target project's actual roles, thresholds, components, and lifecycle terms. A desktop UI pass does not imply mobile support, all-role authorization, release readiness, or full workflow coverage.
