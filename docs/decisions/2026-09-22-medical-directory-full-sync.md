# 医疗目录全量同步实施设计（历史方案）

状态：已由[近20年同步范围决策](2026-09-22-medical-directory-20-year-window.md)取代。以下保留原方案和当时的风险记录，不再作为当前实现依据。

## 1. 本轮业务契约

“全量同步”是长期保留、每次均可主动发起的操作，不根据是否首次执行或本地记录数隐式选择。与“按时间范围同步”共用现有批次创建、执行、查询和分项落库链路。

全量固定覆盖当前已实现的中药、西药、诊疗、耗材；不包含尚未实现的疫苗、血液。不先清库，不将本次未返回记录自动删除或失效，不把时间范围同步称为可靠增量。

100-005 只提供符合条件的数量；100-004 提供同条件下的行号分页及目录内容。两者没有文档明确的快照、稳定排序、变更游标或删除事件。创建时间返回字段不能用来推定查询时间过滤字段。当前规则不能以 2000—2099 等任意宽时间范围充当已确认全量。

## 2. 现有实现与调整位置

| 位置 | 当前事实 | 调整 |
| --- | --- | --- |
| StartBatchDrawer / form.ts | 一个入口，医疗目录必须由用户填时间 | 独立全量、时间范围入口，共用表单；全量不收用户自填范围 |
| StartMasterDataBatchRequest | 类别及可选时间字段，没有模式 | 增加显式模式 FULL / TIME_RANGE；HTTP 校验模式与字段组合 |
| MasterDataBatchServiceImpl.start | 保存请求范围 | 全量从服务端已确认规则解析；固化实际范围与规则版本 |
| MasterDataBatchSnapshot / SummaryVO | 已保存实际范围，没有模式和规则证据 | 原有类型增加必要事实，不创建平行 FullBatch DTO / Service |
| MedicalDirectoryFetchServiceImpl | 根据数量按 100 条完整分页，全部保留在内存 | 保留协议逻辑，增加逐页进度及暂存；不新增另一套全量取数服务 |
| MedicalDirectorySyncServiceImpl | 各类型完整校验后独立提交；逐行查写 | 保留原子边界，改为暂存集与当前目录集合化对账 |
| SoapPhisClient | 统一发送和解析；未留正文 | 后续报文能力统一在此采集，不在业务 Service 重建报文 |

全量/时间范围是同一个“创建目录同步批次”动作的范围选择，不是两种不同业务命令；因此复用请求对象是必要的，字段组合用条件校验明确约束，而不是再逐层复制 Request、Command、Query。

## 3. 关键接口和边界

- 保留批次集合 POST、按 ID run/get/recover 及分项查询路径；增加模式属于明确接口契约变更，前后端及调用方测试同时更新。
- `start(request, actor)`：Controller 校验功能权限、机构范围、枚举及时间字段组合；Service 确认来源配置、规则有效性、执行冲突，解析实际查询范围并在事务内创建批次和审计。
- `run(id, expectedVersion, actor)`：按授权机构范围读取；原子占用执行权，外部调用不占数据库事务。执行前确认固化来源未被配置变更替换，避免开始后换到另一套 HIS。
- `fetchAll(batch, type)`：复用快照中的固定范围；数量和分页共享同一过滤条件。不得读取浏览器当前日期或在每一页重新生成截止时间。
- 目录更新按现有来源系统、机构、类型、来源编码识别记录；更新仅限来源管理的字段，保留平台内部主键和引用。
- 内部执行器使用已持久化执行条件及审计身份，不伪造 HTTP 登录用户。Service 保留业务前置条件，不复制 Controller 的格式校验和认证逻辑。

## 4. 全量规则及批次证据

全量规则需要明确归属来源连接和环境，不允许无意全局回退。规则至少包含经确认的查询起点、结束边界生成方式、医院时区、覆盖类型和停用/空时间记录的覆盖说明，以及确认依据。时间过滤字段、分页一致性限制必须记入依据。

规则应原子保存与审计。若复用参数配置，只能采用已有基础设施能够原子校验和保存的完整规则，不能散存为几个可任意组合的无类型字符串；现有参数配置目前仅注册两个未运行消费的管理默认值，不能假定已具备该能力。

批次保存显式模式、实际起止 UTC 时间、规则版本/依据快照及绑定来源身份。正文凭证不得作为配置快照持久化。规则缺失、失效或与当前连接不一致时，在创建/执行前拒绝，不创建假成功批次。

已有医疗目录批次按实际事实属于时间范围同步，不能补标全量；其他历史批次若无法确定模式，应显示历史未登记，不凭 null 时间推断全量。

## 5. 后台执行、分页与事务

编码可按依赖顺序推进，但交付按完整链路验收：模式、入口、规则校验、固定范围、持久化后台执行、暂存与集合化更新共同完成。不得以只有按钮或模式字段的局部改动宣称整体重构完成。

后台执行以数据库批次状态、执行版本、心跳/占用期限为依据，不只使用单机 @Async 或内存任务列表。执行权失效后旧执行者不能写当前目录；服务重启不能把未完成批次直接算成功或自动重放未知调用。

每类流程：100-005 → 生成所有行范围 → 逐页 100-004 → 保存有界暂存及调用事实 → 校验实际数、唯一数、重复和字段 → 事务内集合化新增/更新并保存该类成功结果。

单页失败停止该类型；其他类型仍可按当前策略处理。暂存只解决本地数据完整性及内存占用，不提供 HIS 快照保证。没有来源快照时，不直接跨时间续跑旧页码；核查后新批次重新从该类数量查询开始。

零声明量可以表示该范围无数据，但不能触发清空；在全量初次验收中还必须与 HIS 同口径事实核对，不能用空批次证明全量覆盖。

## 6. 防重、环境与展示

- 同一用户操作使用稳定 requestKey；重复请求返回或引导读取原批次，不二次执行。若请求标识相同但条件不同，应冲突而非复用另一范围。
- 互斥按照实际写入目录范围，而不是查询日期或同步模式划分。全量与时间范围不能同时改同一目标数据。
- 当前目录唯一键未包含环境。正式部署必须阻止测试来源写入生产目录；需要同库保留多环境目录时必须先完成存储及查询隔离，不能只改变按钮或批次标签。
- 列表和详情显示同步模式、实际范围；分项显示声明数、取得页数、返回数、唯一数、校验结果及新增/更新/未变化。
- HTTP 成功、来源返回成功、校验通过、目录已提交是不同事实；已收到但无法解析的响应记为 `INVALID_RESPONSE`，不得记录成 `NO_RESPONSE` 或业务成功。
- 全量模式不能覆盖结果状态：全量批次仍可能部分完成、失败或存在未知结果。

## 7. 编码前反例

| 反例 | 必须得到的结果 |
| --- | --- |
| 无同步权限但持有机构代码 | Controller 拒绝；不查询 HIS |
| 有功能权限但访问其他机构批次 | SQL 限域，不返回内容或执行 |
| FULL 请求偷偷携带自选时间 | HTTP 校验拒绝；不能绕过规则 |
| 未登记全量规则却直接调 API | Service 拒绝，前端隐藏/禁用不是安全边界 |
| 创建后改变来源连接或规则 | 已固定范围不漂移；身份不匹配时停止执行 |
| 同一范围 FULL 与 TIME_RANGE 并发 | 数据库原子互斥，只允许一个执行者 |
| 取到部分页后超时 | 原目录不因该类型部分数据而更新，保留已取数及错误证据 |
| 数量一致但来源期间有变化 | 不将数量校验宣称为快照一致性证明 |
| 第二次全量数据相同 | 不重复新增，保留每次批次事实 |
| 服务重启或浏览器超时 | 回读持久化状态，不靠自动重发修复 |

## 8. 数据库升级边界

现有开发库已保存真实验收批次、555 条目录和审计。项目 SQL 规范要求未定版修改收敛主版本并重建开发库，但用户要求保留历史数据。因此本轮不得自行清库、改 Flyway 历史、执行 repair 或伪装主版本未执行。

用户已否决新增增量补丁，撤回该建议，不登记未经批准的例外。源码中的相关主版本统一调整，约束、索引、扩展属性及 Mapper 契约同步重构。

用户已明确选择原位调整现有开发库，不建立独立验收库。2026-09-22 预检发现数据库已有 5 个批次、555 条医疗目录、11 条管理审计，Flyway 已执行到 V1000；应用账号和迁移账号均无数据库备份权限，`msdb.dbo.backupset` 未查到该库的备份。原位重建前，必须由有备份权限的数据库管理员完成可恢复备份并核验恢复路径。该步骤是执行条件，不是另建验收库的要求。

源码仍将未确认的医疗目录结构改动收敛到主版本。已执行的 Flyway 历史必须如实保留；不能通过更新旧校验和、执行 `repair`、关闭校验或仅直接手工改表冒充新迁移。原位升级需要在备份后采用经评审的整体重建及数据保留方案，准确重建迁移记录、保留原有批次、目录、审计和引用关系，并完成恢复演练。没有备份和来源口径证据时，不执行破坏性重建，也不声称开发库已经升级或全量同步已获验证。

## 9. 验收及交付分界

1. 模式校验、规则缺失拒绝、实际范围固化、重复请求、越权、模式互斥均有行为测试。
2. 浏览器确认全量入口长期可见，模式切换不残留用户时间；列表/详情能辨别历史范围批次。
3. 经确认的全量规则生效后，另行在获准环境执行新全量批次，核对全部页、唯一数、当前目录及审计。不能用之前 555 条范围验收替代。
4. 完整分页及来源核对成功后才标记该来源全量验收通过；未确认上游语义时，明确未完成部分，不改成功定义迁就结果。
5. 原始报文查看另按交换记录关联与服务端脱敏设计交付，不能以暂存业务字段重建并冒充原始报文。

截至 2026-09-22，工作区已有模式、入口、规则拒绝、范围及端点冻结的源码改动，并通过相应单元与前端检查；数据库尚未升级，新版后端尚未启动，也没有发起新的 HIS 同步。后台执行、分页暂存、集合化更新、原始报文查看以及全量来源口径确认仍未交付，不得将源码检查写成真实全量验收。

当前实现只检查端点主键与行版本；认证配置在调用期间若独立变更，仍可能让不同页使用不同运行配置。后续需将每次调用绑定到同一受控执行配置或在每页前及发布事务中核对认证配置版本，不能仅凭端点行版本宣称来源固定。
