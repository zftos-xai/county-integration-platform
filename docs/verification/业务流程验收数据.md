# 业务流程验收数据

本数据集只用于本地或受控测试环境，通过正式管理接口创建，使权限检查、并发版本、写后回读和审计记录真实发生。不得连接生产环境执行。

## 数据内容

| 页面 | 验收数据 |
| --- | --- |
| 机构管理 | 正常县级机构、正常基层机构、尚未生效机构、已过期机构 |
| 用户管理 | 管理员、只读人员、待分配角色用户、已注销用户 |
| 角色权限 | 全功能验收角色、只读角色、待分配权限角色 |
| 参数配置 | 已启用配置、已配置但停用、未配置三种情况 |
| 数据字典 | 两个字典类型、正常项、停用项和相同排序项 |
| 审计记录 | 上述创建、授权、启停和配置操作产生的真实记录 |
| 运行总览 | 可显示待授权用户、待分配权限角色和未配置参数 |

所有验收机构代码以 `ACCEPT.` 开头，角色代码以 `ACCEPTANCE_` 开头，用户登录名以 `accept.` 开头，字典类型代码以 `ACCEPT_` 开头，不包含患者或真实业务数据。

## 准备数据

先启动后台，并使用已经完成首次改密的平台管理员执行：

```bash
export PLATFORM_ACCEPTANCE_BASE_URL='http://127.0.0.1:18080'
export PLATFORM_ACCEPTANCE_ADMIN_LOGIN='admin'
export PLATFORM_ACCEPTANCE_ADMIN_PASSWORD='<当前管理员密码>'
export PLATFORM_ACCEPTANCE_TEMP_PASSWORD='<至少12个字符的一次性验收密码>'
npm run seed:acceptance
```

脚本可以重复执行：已存在的验收对象会按固定名称、权限、机构范围和启用状态恢复，不会重复创建。若管理员所在机构不是期望的上级机构，可额外设置 `PLATFORM_ACCEPTANCE_PARENT_ORGANIZATION_CODE`。

验收用户首次登录必须修改临时密码。只读用户用于确认按钮隐藏和服务端拒绝写入；待授权用户和空权限角色用于确认页面提醒；已注销用户用于确认登录拒绝。

## 六个页面的完成检查

以下内容按“查看和查询、新增或发起、修改或继续处理、停止使用和删除、权限和数据范围、操作结果和失败处理、操作记录、页面状态”八项共同检查：

| 页面 | 适用操作和保护规则 |
| --- | --- |
| 审计记录 | 查询、组合筛选、详情、按请求编号定位和返回业务对象；由系统新增，普通用户不能修改或删除；医院未确认具体保留年限前不自动清理 |
| 用户管理 | 新增、修改资料、分配角色、设置可查看机构、重置密码、注销和恢复使用；注销本人立即退出；最后一个可登录管理员不得注销或移除管理员角色；历史操作人信息保留 |
| 角色权限 | 新增、修改、分配权限、停用、启用和删除自定义角色；系统保护角色只读；角色仍分配给用户时说明人数并要求先调整用户 |
| 参数配置 | 参数定义只由程序登记；页面新增、修改、停用和删除环境或机构范围的参数值；删除后恢复为尚未配置；敏感值只显示已设置，不返回原值 |
| 数据字典 | 新增和修改类型、字典项，设置排序和启停；类型包含字典项时禁止删除；后台检查数据库真实引用，已使用的字典项只能停用，未使用的才可删除 |
| 机构管理 | 新增、修改、调整上级机构和有效期、撤销和恢复使用；有正常使用的下级机构或可登录用户时禁止撤销；撤销不删除历史业务和操作记录 |

所有写操作使用服务端权限和机构范围检查，携带并发版本；成功后可刷新回读并按业务对象查看操作记录。超时或断网时先重新读取结果，不直接重复提交。

## 清理数据

```bash
npm run cleanup:acceptance
```

清理操作会注销验收用户并停用仍被用户占用的验收角色，删除验收参数值使其恢复为未配置，删除未被业务数据引用的验收字典项和空字典类型，并按下级到上级的顺序撤销验收机构。审计记录不通过清理脚本删除；医院未确认具体保留年限前持续保留。删除接口不能绕过使用关系、系统保护、机构范围或并发版本检查。
