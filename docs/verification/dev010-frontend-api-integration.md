# DEV-010 前端真实API接入记录

## 当前纵切

管理端已接入真实会话、机构、用户、角色权限、参数与字典契约：CSRF令牌、服务端Session登录、当前主体、首次登录改密、退出，以及机构、用户、授权范围、角色、代码注册权限、参数作用域值、字典类型和字典项管理。`/prototype`继续作为独立合成演示入口；正式管理入口不使用演示账号，也不使用`localStorage`代替服务端会话。

## 已实现边界

- 写请求先读取`/api/v1/session/csrf`，并使用服务端返回的请求头名称和令牌。
- 所有请求使用同源会话凭据；密码、Session标识和CSRF令牌不写入本地存储。
- 当前主体的权限代码控制菜单可见性；直接URL访问使用同一权限规则再次检查。
- `mustChangePassword`主体只能进入修改密码页面；修改成功后按后端契约注销并重新登录。
- 400、401、403、404、409、500、网络失败和非平台CSRF响应使用受控文案；存在`requestId`时展示以便定位。
- 后端仍是最终授权边界，前端权限判断不推导机构范围或扩大权限。
- 机构列表完全使用后端返回的数据范围；新增机构必须选择可访问的启用父机构，机构类型只接受项目已确认的代码，不在前端编造枚举。
- 机构修改和启停回传当前Base64 `rowversion`；409时保留编辑内容并提供刷新最新详情，启停操作先刷新列表再显示冲突。
- 机构页覆盖加载、筛选无结果、范围内空数据、只读权限、403、409、网络失败和`requestId`展示；会话过期返回登录页。
- 新增机构会改变当前账号的显式机构范围，成功后前端主动清除旧主体并返回登录页，明确提示重新登录加载最新权限，避免旧Session在下一次请求时突然失效。
- 用户页分别维护基础资料、角色、机构范围和临时密码草稿；当前账号权限、范围、状态或密码变化后主动结束旧主体视图并要求重新登录。
- 角色页只展示后端代码注册权限；系统保护角色不可编辑，非系统角色的资料更新携带Base64 `rowversion`，权限替换不允许提交未注册代码。
- 参数页只呈现后端代码注册定义，不提供任意键编辑器；环境、机构作用域、类型和数值/格式约束由定义驱动，敏感已有值不回填表单。
- 字典页以类型和字典项分层维护平台自身字典；稳定代码创建后只读，类型和字典项更新均携带Base64 `rowversion`。

- 后端改用`18080`启动，Vite管理端在`5173`通过同源代理连接`http://127.0.0.1:18080`；不再依赖已被其他服务占用的`8080`。
- SQL Server 2012实例成功连接，Flyway验证V0100至V0500共5个主版本；应用健康检查返回`UP`。
- 在真实Spring Boot、SQL Server和Vite代理链路完成一次性初始化、首次登录、强制改密、重新登录和Session续用。

- Chrome真实管理员会话已确认角色列表、9项后端注册权限、系统角色只读保护、抽屉焦点进入、Escape关闭和焦点恢复；本轮未执行角色写入。
