# BD-00 PHIS接口契约验证记录

验证日期：2026-09-18
当前结论：WSDL入口和离线编解码已验证；真实`100-001/100-002`业务调用尚未执行

## 1. 验证范围

本次只验证用户提供的基层HIS测试服务WSDL和平台离线编解码边界，不发送厂商编号、用户名、密码、验证码或其他凭证，不保存真实服务地址和原始配置记录。

## 2. WSDL只读验证结果

对用户提供的测试服务执行只读WSDL请求，结果如下：

| 检查项 | 实际结果 |
| --- | --- |
| HTTP结果 | `200 OK` |
| 服务实现 | ASP.NET WebService |
| 目标命名空间 | `http://tempuri.org/` |
| `PHIS_Interface` | 存在 |
| `PHIS_Interface`入参 | `TradeCode`、`InputParameter`，均为字符串 |
| SOAP 1.1动作 | `http://tempuri.org/PHIS_Interface` |
| SOAP 1.2动作 | `http://tempuri.org/PHIS_Interface` |
| `HIS_Interface` | 同一WSDL中也存在，不能仅凭方法存在判断业务应调用它 |
| 服务地址协议 | WSDL只公布HTTP地址 |

接口规范指定基础数据调用`PHIS_Interface`，实际WSDL也提供该方法，因此平台以`PHIS_Interface`作为当前确认的业务操作。`HIS_Interface`只记录为同服务中的另一个方法，不作为基础数据默认入口。

平台已根据实际WSDL允许受控HTTP或HTTPS服务地址。配置保存WSDL公布的`/WebService.asmx`服务地址；`?op=PHIS_Interface`是ASMX操作页写法，不作为SOAP基础地址保存，实际操作由SOAPAction和请求体确定。

## 3. 已完成实现

- 使用SOAP 1.1编码`TradeCode`和JSON格式的`InputParameter`。
- 使用HTTP POST调用WSDL公布的`/WebService.asmx`地址，并设置已确认的SOAPAction。
- 支持正式接口实际使用的HTTP或HTTPS服务地址，不自动跟随重定向。
- 服务地址、超时时间和凭证引用按“外部系统 + 环境 + 机构”保存在数据库，并按当前机构精确读取。
- 多个机构可以共用服务地址，但不得共用或回退使用其他机构的授权码；找不到本机构启用配置时调用直接失败。
- 管理端正式页面已经接入真实外部系统、机构服务地址和机构凭证引用API；新连接先以停用状态创建，复核后再启用。
- HIS调用采用单一业务服务和SOAP适配器；地址及凭证由配置域按机构和环境精确解析，业务交易不能读取其他机构凭证。
- 当前凭证提供器支持`env://VARIABLE_NAME`引用，变量值按机构保存厂商编号、用户名、密码和授权码JSON；页面只返回“已配置”状态。
- 分别处理非成功HTTP状态、连接/读取超时、调用中断和网络通信失败，异常不包含目标响应正文。
- 由XML写入器完成特殊字符转义，不拼接未转义业务参数。
- 禁止文档类型声明、外部DTD、外部Schema和外部实体。
- 从`PHIS_InterfaceResult`提取内层JSON。
- 兼容`result/msg`与`Result/Msg`字段名。
- 兼容结果码为数字或字符串。
- 只接受已确认的`1`成功和`0`失败；其他结果码拒绝进入业务处理。
- 异常不携带原始SOAP、JSON、验证码或业务数据。

## 4. 尚未完成

- 旧平台厂商编号和验证码是否获准由本项目使用。
- 医院是否批准当前环境变量凭证来源用于正式环境；如改用医院密钥库，只替换凭证提供器实现，数据库仍保存机构级引用。
- `100-002`是否适用于后台定时任务，以及验证码有效期和轮换规则。
- `100-001`正常、失败、无效厂商编号和超时响应样例。
- `100-002`正常、失败、无效账号和验证码过期响应样例。
- 连接超时、读取超时和SOAP Fault的真实返回特征。

在上述事项确认前，平台不写入真实凭证、不启用该服务地址，也不把WSDL可访问表述为`100-001/100-002`业务验证通过。
