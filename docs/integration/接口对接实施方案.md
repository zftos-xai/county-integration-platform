# 接口对接实施方案（工程起步版）

## 范围与当前状态

平台只承担县人民医院与所辖基层卫生院之间的接入、转换、交换状态、审计和对账，不替代 HIS 等业务系统。现有接口清单、矩阵和参考文档位于 `../reference/interfaces/`，是需求输入，不等同于双方签署的正式合同。75 项是总体范围基线，不在本文推定启用顺序、字段或完成状态。具体接口的优先级、责任人和阻塞项由项目管理台账维护，不在工程仓库复制第二份台账。

目前已具备后端模块骨架、管理 API 基线、SQL Server 首版迁移、请求编号、默认拒绝的安全配置、交换记录只读查询和构建检查。医院身份认证、患者对应规则、正式合同与脱敏样例、测试和生产网络及系统凭证尚需外部确认。上述条件不齐的接口标记为 `CONTRACT_BLOCKED`（对应项目台账“条件不具备”），不得开始真实厂商适配或宣称联调通过。

## 对接流程与交付物

| 阶段 | 必须确认或完成 | 工程交付与放行依据 |
|---|---|---|
| 1. 范围与准入 | 逐项确认双方系统、调用方向、接口版本、启用范围、业务及技术负责人、验收负责人；正式合同、脱敏请求/响应、地址申请、网络、认证与凭证交付方式 | 项目台账形成书面结论；条件不足停在 `CONTRACT_BLOCKED` |
| 2. 合同设计 | 字段类型/值域、编码与单位、时间语义、患者及机构关联、权限用途、结果码、查询/撤销、超时及重复处理 | 采用 [单接口工程准入模板](../../contracts/interface-onboarding-template.md)；`contracts/openapi/` 存批准后的版本化定义，`contracts/mappings/` 保存经确认的映射；只提交合规脱敏样例 |
| 3. 基础能力 | 确认医院身份接入、机构隔离、数据库账号和迁移策略、请求追踪、审计、告警、备份恢复、环境隔离 | 安全评审、SQL Server 实测迁移及恢复记录、授权和越权测试；身份机制未批准前保持默认拒绝 |
| 4. 单接口实现 | 按业务模块组织 Controller/Service/Repository/Mapper/Client；读写职责分离；明确防重复键、结果未知的查询/对账路径 | 代码、版本化配置/SQL、单元测试、合同测试及另一名开发人员的评审记录 |
| 5. 双方联调 | 正常、无权限、重复、失败、超时、目标系统不可用、结果未知、撤销及恢复；按机构、业务单号与请求编号串联 | 双方在授权测试环境使用正式脱敏样例，保存请求、响应、数据库状态和处理记录的脱敏证据 |
| 6. 验收与上线 | 对账差异闭环、安全/性能、备份恢复、监控、版本与回退；双方签署验收 | 合同版本、映射校验值、部署制品、测试及验收证据一一对应；未通过不得标记完成 |

外部 HTTP 超时不等于业务失败；结果未知时先查目标系统或对账，不能直接再次写入。涉及敏感数据的日志和样例须遵守 `../standards/` 与 `../../contracts/samples/README.md` 的限制。

## 第一轮工程任务

1. 与医院/HIS/基层系统联系人核定优先接入接口及其正式合同、调用方向、责任人和验收场景；项目负责人在台账中记录结论。
2. 确认身份与机构授权模型、患者对应规则、测试网络和 SQL Server 独立账号；未确认前继续保持管理 API 默认拒绝、嵌入端等待安全上下文。
3. 针对获批的一项接口建立独立合同版本和脱敏样例，经双方确认字段映射后再实现 `exchange/client` 与业务处理；不要用参考接口文档直接生成生产适配器。
4. 在获批环境验证数据库迁移、合同与异常路径，并形成可追溯的联调及恢复记录。当前的 Maven `verify` 和前端构建只能证明工程检查，不能代替 SQL Server、网络或双方联调验收。

实施时以 [工程建设规范](../standards/) 和 [模块化单体决策](../decisions/DEC-0001-java17-modular-monolith.md) 为边界。归档规范中的 Java 21 与当前已采用的 Java 17 决策不一致；当前代码、Maven 与 CI 统一使用 Java 17，变更基线须另行决策。
