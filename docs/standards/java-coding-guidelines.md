# Java 与 AI Coding 规范（项目执行版）

本规范适用于本项目所有 Java 源码、测试、MyBatis 映射、SQL 迁移及由 AI 辅助产生的相关修改。规范参考《Alibaba Java Coding Guidelines》的命名、常量、集合、并发、异常、日志和测试原则，并以本项目 Java 17、Spring Boot 3.5、MyBatis、SQL Server 2012 SP4 和工程决策为准。

AI 生成内容只能作为待评审的工程修改。提交者对需求理解、正确性、安全性、兼容性、测试和文档承担责任。任何生成结果都不能代替代码评审、真实数据库验证或双方系统联调。

## 1. 规范优先级与基本原则

- 按“用户明确要求 > 已确认接口规范和安全要求 > 项目工程决策 > 本规范 > 通用编码习惯”的顺序处理冲突，并在交付说明中指出实质冲突。
- 修改前先阅读所在模块、调用方、测试、迁移脚本和接口材料，不凭类名或局部代码猜测业务规则。
- 只修改完成当前任务所需的内容；无关问题记录为风险，不顺带大范围重构、升级依赖、格式化或改名。
- 不编造接口字段、状态码、患者匹配规则、机构权限、数据库结构、配置值、联调结果或性能数据。
- 信息不完整时采用安全默认值：拒绝未授权访问、停止不确定写入、保留可追踪状态，并明确待确认项。
- 项目文档默认使用 Markdown；接口来源文件按 `docs/reference/interfaces/` 的例外规则保留原始格式。

## 2. AI Coding 工作流程

### 2.1 开发前

开始编码前必须确认：

1. 任务目标、输入输出、调用方向和范围边界。
2. 身份、机构数据范围、患者数据等级及脱敏要求。
3. 正常、失败、超时、重复、结果未知和回退场景。
4. 是否涉及接口规范、数据库迁移、配置、依赖或兼容性变化。
5. 可执行的验证方式，以及哪些结论必须留到真实环境确认。

不得为了让演示或测试通过而放宽认证、跳过机构隔离、硬编码凭证、伪造成功结果、吞掉异常或关闭迁移校验。

### 2.2 实现中

- 优先复用已有结构和约定，保持变更小而完整；新增抽象必须解决已经出现的问题。
- 每次修改同步检查调用方、异常路径、权限边界、事务、日志、测试和文档。
- 不删除尚未确认用途的兼容字段、数据库列、状态值或审计信息。
- 不用占位实现伪装完成功能。确需占位时明确返回未配置或暂不可用状态，不返回合成的业务成功数据。
- 不引入未经说明的新框架、代码生成器、运行时反射或全局工具类。

### 2.3 交付前

- 检查实际差异，移除调试代码、临时文件、无关格式变化、失效注释和未使用依赖。
- 运行与变更匹配的静态检查、测试或构建；无法运行时说明具体缺失条件。
- 报告修改内容、原因、验证证据及仍需医院、厂商或真实环境确认的风险。
- 没有相应环境和证据时，不声称“已完成联调”“可上线”或“兼容 SQL Server 2012”。

## 3. 注释与 Javadoc

### 3.1 强制要求

- 所有新增或修改的类、接口、枚举和 `record` 必须添加类级 Javadoc。
- 所有新增或修改的方法，包括构造方法、公开方法、包内方法和私有方法，必须添加方法级 Javadoc。
- 重写方法可沿用上级方法的使用约定，但必须保留 `@Override`；只有接口契约已经完整且实现没有新增约束时才可只使用 `{@inheritDoc}`。本实现涉及事务、外部调用、权限、审计、重试、结果未知或其他副作用时，必须补充实现特有说明。
- Mapper 方法必须说明读写目的、机构隔离条件、排序/分页规则和无结果含义。
- Controller 方法必须说明调用目的、授权边界和响应含义；Service 方法必须说明业务规则、事务、防重复规则和失败时的含义。
- 与数据表关联的实体、快照、聚合投影、查询投影和写入参数，类级 Javadoc 必须使用带架构名的完整表名（例如 `dbo.sys_user`），说明主表、关联表或持久化目标，并用“业务说明”解释该表在业务流程中的用途。聚合投影必须明确它不对应独立表；写入参数必须明确它是否为完整表行。
- 注释必须随实现同步更新。注释与代码冲突视为缺陷，不保留失效的历史描述。

### 3.2 内容要求

类级 Javadoc 至少说明业务功能、所属模块、职责边界、关键依赖或安全约束；有状态组件还要说明生命周期和线程安全。

方法级 Javadoc 根据实际情况说明：

- 业务动作及调用前提；
- 参数的业务含义、格式和取值范围；
- 返回值、空值和“未找到”的含义；
- 数据写入、外部调用、审计和事务等副作用；
- 业务异常、超时和结果未知情况；
- 写操作的防重复编号、重复请求和重试规则。

`@param`、`@return`、`@throws` 应提供调用者需要的信息，不写“获取名称”“返回结果”这类只复述标识符的内容。Javadoc 必须先有职责摘要，每个块标签独占一行；`record` 的每个组件都必须有同名 `@param`。行内注释解释业务原因、算法选择、安全约束和兼容性处理，不逐行翻译代码。

```java
/**
 * 查询指定机构最近的接口交换记录。
 *
 * <p>结果严格限制在调用者获准访问的机构范围内，查询不会触发补发。</p>
 *
 * @param organizationCode 平台统一机构代码，不是机构名称或外部系统代码
 * @param limit 最大返回数量，取值范围为 1 至 100
 * @return 按接收时间倒序排列的记录；没有记录时返回空列表
 * @throws AccessDeniedException 调用者无权访问目标机构时抛出
 */
public List<ExchangeRecordSummary> findRecent(String organizationCode, int limit) {
    // 结果未知的记录只能查询和核查，不能因查询动作触发再次写入。
    return repository.findRecent(organizationCode, Math.min(limit, 100));
}
```

## 4. 命名、结构与可读性

- 基础包统一为`cn.zqkj.platform`。系统管理归入`system`，交换功能归入`exchange`，内部统一使用`controller / domain / mapper / service / service.impl`分包；需要定义领域专属异常时统一增加`exception`包。Service接口使用业务名称，默认实现使用`Impl`后缀。`domain`固定按`dto / model / vo`区分输入、内部模型和输出，输出类使用`VO`后缀。包名全小写，类用PascalCase，方法和变量用camelCase，常量用`UPPER_SNAKE_CASE`。
- 使用统一业务术语，避免拼音、不明确缩写及含义不清的 `data`、`info`、`handle`、`process`。
- `controller`包只允许Controller；Controller负责协议转换和输入校验并只依赖Service接口。`service.impl`负责业务规则与事务；`mapper`包只允许MyBatis Mapper接口，不增加Repository和`MyBatis...Repository`适配层；Client负责获批外部调用。
- 请求和响应对象不得直接暴露数据库实体。对外接口规范、领域和持久化模型不一致时应明确转换边界。
- 方法保持单一目的；复杂条件提取为有业务含义的方法，避免深层嵌套、超长参数列表和用布尔值控制多条流程。
- 优先使用构造器注入和创建后不能修改的对象；只读传输结果可用 `record`。禁止通过静态可变状态共享请求数据。
- Spring、安全和Web技术装配按职责放入`framework`；`common`仅允许统一响应、异常等边界明确且不含业务规则的类型，不创建无边界的`shared`或`utils`包。
- 业务域专属异常统一放在`<业务域>/exception`，跨业务且语义稳定的公共异常才允许放在`common/exception`。异常类不得夹在`controller`、`client`、`service`或`service.impl`中；名称应表达失败语义，不使用`ServiceException`、`ClientException`等仅描述技术层次的笼统命名。

## 5. Java 基础实践

- 禁止通配符导入、空 `catch`、异常吞没、裸类型集合和不受控强制类型转换。
- 返回空集合而不是 `null`；是否允许 `null` 必须通过类型、校验或 Javadoc 明确。
- 用常量、枚举或值对象表达稳定取值，避免魔法字符串和数字；外部未知枚举值按接口规范处理。
- 字符串和包装类型使用值比较；金额使用 `BigDecimal`，明确币种、精度和舍入规则。
- 明确业务时间、接收时间、处理时间和时区；跨系统时间优先携带偏移量，不混用本地时间和 UTC。
- 使用 try-with-resources 管理资源；不得手工创建无生命周期管理的线程池或无限等待。
- Stream 只用于清晰的数据转换；复杂分支、副作用或异常处理使用普通循环。

## 6. 接口、校验与错误处理

- 外部输入必须校验必填性、长度、格式、合法值域、机构权限和数据范围；前端校验不能替代服务端校验。
- API 返回稳定业务错误码，不返回堆栈、SQL、内部地址、密钥或患者原始内容。
- 区分参数错误、认证失败、授权失败、业务拒绝、目标系统失败、超时、结果未知和内部错误。
- 外部调用必须设置连接和读取超时。只有确认目标端未处理或操作重复执行也不会产生重复结果时才能自动重试；结果未知时先查询或对账。
- 接口版本、字段、签名、编码和状态映射只来自已确认的接口规范；规划对照表、原型和示例不能直接作为生产接口规范。
- API 接口规范变化必须同步 OpenAPI、调用方、测试和兼容性说明；破坏性变化应使用新版本或明确迁移方案。

## 7. 事务、并发和防止重复提交

- Service 明确并缩短事务边界；外部 HTTP/SOAP 调用不得长期占用数据库事务。
- 写操作必须定义业务唯一键或防重复编号，并以数据库唯一约束作为最终保障；先查后写不能单独防重复。
- 并发更新采用行版本、条件更新或明确锁策略，处理影响行数为零的情况，不用单机内存锁保证跨实例一致性。
- 状态变化必须验证前置状态并记录操作人、请求编号和时间，禁止任意覆盖终态或跳过审计。
- 超时、连接中断和响应解析失败不能直接等同于目标端写入失败，必须进入结果未知、核查或对账流程。
- 失败后补救和重试任务应限制次数、退避时间和并发量，并提供人工停止和恢复手段。

## 8. SQL Server 与 MyBatis

- 数据库统一为 Microsoft SQL Server 2012 SP4，兼容级别 110；SQL、驱动、Flyway、事务和锁行为必须在同版本验证。
- 不使用 SQL Server 2012 之后才提供的语法和功能；函数、分页语法和索引选项必须核对兼容性。
- MyBatis 值参数使用 `#{}`；`${}` 仅用于固定白名单转换后的标识符，禁止直接拼接外部输入。
- 构造器 `resultMap` 必须与目标 Java `record` 的组件数量、顺序、Java 类型和结果列名逐项一致；布尔状态、并发版本及业务别名按项目约定或显式例外核对，禁止仅凭多个相同 Java 类型“碰巧可构造”判断映射正确。
- Mapper XML 一致性测试必须自动发现全部业务目录，不得维护容易遗漏新模块的硬编码文件清单。新增结果模型或 Mapper 时，必须通过全量构造映射一致性测试；任何列改名、字段增删或顺序变化必须同时修改模型、`resultMap`、复用列清单和测试。
- 查询结果优先使用与 `resultMap` 配套的可复用列清单并显式列出结果列；静态测试负责核对模型和映射合同，SQL Server 2012 集成测试负责以真实结果集元数据验证列是否存在、别名、JDBC 类型、空值和实际反序列化，二者不得互相替代。
- MyBatis Mapper XML中凡是能够安全添加字段注释的位置都必须添加准确注释，不限定于`<constructor>`。包括但不限于`<id>`、`<result>`、`<idArg>`、`<arg>`、`<association>`、`<collection>`内的字段映射，可复用列清单，以及`SELECT`、`INSERT`、`UPDATE`和条件语句中的业务字段。注释应紧邻字段定义、映射项或明确列清单，说明字段的业务含义、时间规则、敏感边界或特殊空值含义；不得只依赖列名、Java属性名、Java类型或Java记录注释推断含义。相同字段集中定义并复用时可在定义处统一注释，不要求在每个引用点机械重复；字段增删、来源变化或含义变化时必须同步更新注释。
- 查询明确列名、机构过滤和稳定排序；列表必须分页或限量，避免 `SELECT *`、无边界查询和逐行重复查询。
- SQL迁移必须遵守[SQL Server建设与迁移脚本规范](sql-coding-guidelines.md)：一个业务一个主版本，未进入共享环境的修改合并回主版本，已进入共享环境后才允许增加引用该主版本的补丁。
- 主版本和补丁必须说明需求依据、数据边界、时间规则、回退方案以及表、字段、约束和索引用途；不得用无注释的DDL或连续小脚本掩盖未稳定设计。
- 唯一约束、检查约束和索引应与防止重复的规则及实际访问路径一致。
- 生产迁移前备份并验证恢复；DDL、大批量更新和索引操作应评估锁、日志空间、窗口及对 HIS 的影响。

Mapper XML字段注释示例：

```xml
<resultMap id="managedUser" type="cn.zqkj.platform.system.domain.vo.ManagedUserVO">
    <constructor>
        <!-- 平台用户内部主键 -->
        <idArg column="id" javaType="java.lang.Long"/>
        <!-- 平台本地登录名 -->
        <arg column="login_name" javaType="java.lang.String"/>
    </constructor>
</resultMap>

<sql id="userColumns">
    id,                  /* 平台用户内部主键 */
    login_name,          /* 平台本地登录名 */
    password_changed_at  /* 最近一次完成密码修改的UTC时间 */
</sql>
```

## 9. 安全、隐私与日志

- 每个读写入口都必须执行身份认证、功能权限和机构数据范围校验；隐藏菜单或客户端机构代码不构成授权。
- 患者关联、跨机构查询、报告调阅、再次写入、权限配置和审计查询必须保留可复核记录。
- 密码、Token、Cookie、密钥、连接密码和私钥只能通过批准的安全配置渠道提供，不得进入代码、仓库、测试或日志。
- 日志使用参数化占位符并保留 `requestId`；禁止记录完整身份证号、手机号、患者姓名组合、报告正文或未脱敏报文。
- 正常业务拒绝不记录堆栈；未知系统异常保留受控堆栈；重复高频错误必须防止日志风暴。
- 审计日志与运行日志分离。审计事件包含操作人、动作、对象、结果、时间和请求编号，业务代码不得任意修改审计结果。
- 禁止通过关闭认证、证书校验或权限检查解决环境问题；临时安全例外必须有适用环境、到期条件和审批记录。

## 10. 异常、配置与依赖

- 只捕获能够处理或补充业务含义的异常；保留原始原因，不把所有异常转换为成功或普通业务错误。
- 配置项必须有清晰名称、类型、合法范围和安全默认值；生产必填配置缺失时应启动失败。
- 环境地址、账号、机构代码和凭证不得硬编码；环境差异通过配置表达，业务逻辑不得按环境分叉。
- 新依赖必须说明必要性、许可证、维护状态、安全风险、Java 17 兼容性和传递依赖。
- 不擅自升级父工程、框架、驱动或锁文件；依赖升级必须独立说明兼容性并运行相应测试。

## 11. 测试规范

- 测试名称表达“条件—动作—预期”，使用 Arrange/Act/Assert 或 Given/When/Then，避免在一个测试中混合无关场景。
- 单测覆盖参数边界、权限隔离、状态变化、重复请求、结果未知、异常转换和敏感数据处理。
- 数据库测试覆盖 SQL Server 2012 的空库和升级迁移、唯一约束、并发锁、索引、时间精度和失败回滚。
- 接口规范获批后使用正式已删除或遮盖敏感字段的样例增加接口兼容性测试；测试替身不能代替真实网络、数据库和双方联调。
- 修复缺陷时增加修复前失败、修复后通过的回归测试；纯文本、注释或无行为变化的整理不机械添加测试。
- 测试必须可重复，不依赖执行顺序、真实时间、公共环境残留数据或不可控外部服务。
- 不删除、跳过或放宽测试来掩盖问题；调整断言时说明原规则为何失效。

## 12. 代码评审与完成定义

- [ ] 实现符合已确认需求、接口规范和工程决策。
- [ ] 新增或修改的类和方法均有准确 Javadoc，复杂逻辑有必要的原因说明。
- [ ] 输入校验、身份认证、机构隔离和敏感数据处理完整。
- [ ] 写操作定义防重复规则、事务、并发、重试、结果未知和审计行为。
- [ ] SQL 与迁移符合 SQL Server 2012 SP4 和兼容级别 110。
- [ ] MyBatis Mapper XML中可注释的字段定义、映射、列清单、写入项和业务条件均有准确字段注释，且注释与当前字段含义一致。
- [ ] Java记录组件、构造器`resultMap`和查询结果列在数量、顺序、名称、类型及空值边界上保持一致，并通过自动发现全部Mapper的一致性测试。
- [ ] 每个业务只有一个主版本，补丁归属、编号、数量和注释通过SQL迁移自动检查。
- [ ] 没有硬编码凭证、真实患者数据、调试输出、伪造结果或无负责人 TODO。
- [ ] 测试覆盖主要正常和高风险失败路径，适用的构建及静态检查通过。
- [ ] 接口、配置、数据库和运维变化已同步 Markdown 文档。
- [ ] 差异中没有无关重构、生成文件、临时文件或未解释的依赖变化。
- [ ] 交付说明列出验证证据及仍需真实环境确认的限制。

身份接入、患者对应、跨机构访问、重复写入、数据库迁移、接口映射和审计逻辑必须由另一名开发人员复核。涉及生产数据、权限边界或不可逆数据变化时，还须按医院流程完成专项审批和回退演练。

## 13. 自动检查范围

`backend/checkstyle.xml`通过Maven `validate`执行，当前覆盖制表符、文件结尾、通配符导入、Java标识符命名、空`catch`以及类和方法缺少Javadoc。Maven `verify`还使用Javadoc DocLint生成生产代码文档，任何警告均使构建失败。`tools/verify-sql-migrations.mjs`检查SQL主版本、补丁、命名、注释和脚本膨胀；`tools/verify.sh`、`tools/verify.ps1`和CI均会执行。

`tools/verify-java-comments.mjs`检查Javadoc摘要、块标签排版、`record`组件说明，并自动发现MyBatis映射模型；所有发现的映射模型都必须登记完整表名与业务说明。登记表名还会与迁移脚本交叉核对。`tools/verify-mapper-comments.mjs`自动检查Mapper XML字段映射、复用列清单、写入列清单和SQL语句是否具备规定位置的注释。两项检查均由`tools/verify.sh`、`tools/verify.ps1`及CI强制执行。

自动检查只能证明注释结构、必要关键字和表名关联完整，不能判断业务含义是否准确，也不能单独证明SQL Server 2012实际兼容。提交者和评审者仍须检查需求依据、数据边界、注释语义和DDL含义，并在条件具备后执行真实数据库验证；扩展自动规则时必须先修复存量内容，不能用大量豁免让检查名存实亡。
