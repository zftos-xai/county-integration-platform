# Java 编码规范（项目执行版）

本规范参考《Alibaba Java Coding Guidelines》的命名、常量、集合、并发、异常、日志和单元测试原则，并以项目现有工程建设规范和 Java 17 / Spring Boot 3.5 / MyBatis 决策为准。它不声称完整覆盖或逐条认证任何特定版本的阿里规范。自动检查只覆盖下述可机械判断的部分，其余须通过评审和测试验证。

## 命名与结构

- 包名全小写并按 `cn.zqkj.<业务模块>` 划分；类 PascalCase、方法/变量 camelCase、常量 `UPPER_SNAKE_CASE`，避免拼音与不明确缩写。接口版本、机构、患者及业务单号使用工程规范中的统一术语。
- 按业务模块归属代码和表写入权；Controller 负责参数校验及协议响应，Service 管业务规则和事务边界，Repository/Mapper 管数据库访问，Client 管获批外部系统调用。请求/响应对象不得直接暴露数据库实体。
- 使用不可变对象表达只读结果（适用时可用 Java record）；类型和集合名称应表达业务含义。公共 `shared` 只放稳定的跨模块技术能力，不存业务规则。

## Java 实践

- 禁止通配符导入、空 `catch` 和未解释的异常吞没。捕获异常应按业务失败、认证/授权失败、外部系统失败、结果未知区分，不回传堆栈或患者原文。
- 常量替代散落的魔法值；集合优先参数化类型，返回空集合而非 `null`；不要修改遍历中的集合。外部输入先校验长度、格式、业务权限和合法值域。
- 精度敏感金额使用 `BigDecimal` 并明确币种、精度和舍入规则；时间写明时区及业务/接收语义，具体单位和转换以正式合同为准。
- Service 事务应尽可能短；外部 HTTP 调用不得长期占用数据库事务。对可能重复的写入设计数据库约束和明确的幂等结果；超时未知不能当作可直接重试的失败。
- 日志使用参数化占位符，保留 `requestId` 等定位信息；禁止打印密码、Token、Cookie、未脱敏报文或患者身份组合。对外错误码应稳定，日志和响应职责分离。

## SQL、测试与评审

- MyBatis 使用 `#{}` 参数绑定，动态表名/排序字段必须白名单控制；禁止用 `${}` 拼接未经验证的外部输入；按需查询字段、限定机构范围和分页，迁移脚本使用 Flyway 版本化管理。
- 单测覆盖参数边界、权限隔离、状态变化和防重复规则；获批合同后增加正式脱敏样例的合同测试，SQL Server 迁移/并发和双方系统联调分别留下证据。测试替身不能代替真实环境验收。
- 身份接入、患者对应、跨机构访问、再次写入、数据库脚本及映射变更必须由另一名开发人员复核。合并前检查格式门禁、测试、合同与文档同步及敏感数据风险。

## 自动化范围

`backend/checkstyle.xml` 通过 Maven `validate` 执行，覆盖制表符、文件结尾、通配符导入、Java 标识符命名和空 `catch`；`mvn -f backend/pom.xml verify` 与 CI 均会执行。规则故意保持在当前代码可验证的小集合，不能代替 Alibaba 规范全文、人工评审、SQL 安全检查或接口验收。扩展规则时先验证现有代码和测试，再更新本说明。
