# 易懂用语对照表

本表用于 README、项目文档、页面文案、对外返回信息和会出现在日志中的名称。纯代码内部的标准技术名称可以保留，但面向业务人员的文字必须按下表表达。

## 扫描结果

| 位置 | 发现的主要原用语 | 处理方式 |
| --- | --- | --- |
| `README.md`、`docs/plans/` | 基线、底座、链路、准入、P0、端到端、证据闭环 | 按实际阶段、数据传递步骤、开始条件和验收记录逐句改写 |
| `docs/design/`、`docs/decisions/` | 状态语义、业务事实、治理、证据、快照、分流 | 改为状态含义、已确认结果、管理、核查依据、当时保存的规则和分类处理 |
| `docs/standards/`、`plugins/team-engineering-standards/` | 合同、治理基线、制品、门禁、幂等、路由 | 改为接口规范、当前工程规则、发布文件、自动检查、重复提交规则和页面地址 |
| `web-admin/src/`、`web-embed/src/` | 准入状态、证据信息、处理路径、原型隔离、端到端功能 | 改为是否允许新请求、可供核查的信息、处理方式、原型与正式页面分开、从页面请求到数据库结果 |
| `backend/src/` | 英文校验错误、scope、endpoint、rowversion 等直接返回内容 | 对外消息改为具体中文；保留字段名，并解释服务地址、可访问机构和 SQL Server 行版本号 |
| `interface-specs/` | contract、baseline、英文接口摘要和响应说明 | 目录与文件改名，说明统一为接口规范、当前运行信息和中文接口说明 |
| `docs/reference/interfaces/` | 上游 PDF、Excel、图片和转换稿中的原始用语 | 按仓库规则保留原文，避免把上游原始资料误改成平台确认结论 |

下表记录统一后的用语。原用语只在本表的“原用语”列保留，供复查和阻止旧写法重新进入项目。

| 原用语 | 统一用语 | 适用场景 |
| --- | --- | --- |
| 接口合同、技术契约 | 接口规范 | 接口的字段、请求、响应、版本和错误处理约定 |
| 合同版本 | 接口版本 | 某个接口规范的版本 |
| 合同校验 | 接口格式校验 | 检查请求或响应是否符合接口格式 |
| 合同测试 | 接口兼容性测试 | 检查实现与已确认接口规范是否一致 |
| `CONTRACT_BLOCKED` | 接口资料不完整 | 缺少接口规范、样例、网络、认证方式或责任人，暂时不能开发 |
| 基线 | 确认版本、当前约定、现状记录或参考值 | 按句子实际含义选择，不作统一的逐字替换 |
| 制品 | 构建结果、发布文件或安装包 | 按实际交付内容选择 |
| 数据治理 | 数据整理与质量管理 | 数据校验、修正、去重和质量检查 |
| 运行治理 | 运行处理 | 告警、异常和审计等页面分组 |
| 能力目录 | 对外接口目录 | 可供其他系统调用的接口清单 |
| 运行单元 | 独立程序或服务程序 | 部署与运行说明 |
| 权威来源 | 负责维护该数据的系统 | 基础数据来源说明 |
| 查询副本 | 用于查询的数据副本 | 为查询而保存的副本 |
| 来源证据、证据链 | 来源记录、完整的数据来源记录 | 普通数据的来源和处理历史；审计、法律和验收材料仍可使用“证据” |
| 连接器、适配器 | 接入程序 | 调用外部系统并转换数据格式的程序 |
| 状态语义 | 状态含义 | 说明状态代表的当前问题和下一步 |
| 数据域 | 数据类别 | 按业务用途划分的数据类别 |
| 上下文 | 当前信息、访问条件、就诊信息或请求信息 | 按具体对象表达，不单独使用“上下文” |
| 查询模型 | 查询数据 | 专供页面或接口查询的数据 |
| 主索引 | 居民身份关联记录 | 关联同一居民在不同系统中的标识 |
| 可观测性 | 日志、监控和故障排查 | 运行保障说明 |
| 故障域 | 可能同时受同一故障影响的范围 | 部署和风险说明 |
| 判权 | 检查访问权限 | 权限检查 |
| 幂等 | 重复提交不会产生重复结果 | 写入、重试和对账规则 |
| 幂等键 | 防重复编号 | 识别同一次业务提交的编号 |
| Schema | 数据格式定义，或数据库架构名 | 接口场景表示数据格式；数据库场景表示对象所属的命名空间 |
| 路由 | 页面地址、页面分发规则或服务地址 | 按页面导航、请求分发或外部服务选择的实际含义表达 |
| 隔离区 | 暂存待处理区 | 未通过检查、等待人工处理的数据区域 |
| 不可变 | 创建后不能修改、发布后不能直接修改 | 按对象的实际限制说明 |
| 当前指针 | 当前使用的版本编号 | 版本选择说明 |
| P0 | 开工前必须解决、开工准备阶段 | 问题优先级与项目阶段分别按实际含义表达 |
| PoC | 技术试验 | 验证关键技术是否可行 |
| ADR | 架构决策记录 | 记录重要技术选择和原因 |
| SLO | 服务可用性和性能目标 | 运行目标 |
| RPO | 最多允许丢失多长时间的数据 | 备份与恢复要求 |
| RTO | 故障后最长恢复时间 | 备份与恢复要求 |
| 闭环 | 从请求到确认结果的全部步骤 | 必须继续说明谁在什么时候做什么，以及如何确认结果 |
| 模块化核心 | 按明确职责拆分的核心程序 | 只有确需说明程序结构时使用具体职责，不保留该组合词 |
| 治理资产 | 可复用的规则、清单或文档 | 直接说清实际内容 |
| 处理链路 | 处理步骤或数据传递过程 | 列出主要步骤和确认结果的方法 |
| 业务事实 | 已确认的业务结果或记录 | 说明由哪个系统、记录或人员确认 |
| 证据闭环 | 从执行到验收的完整记录 | 仅用于正式验收；普通处理改为处理记录 |
| 状态流转 | 状态变更 | 同时说明允许从什么状态改成什么状态 |
| 准入条件 | 开始开发前必须具备的资料、启用前检查项 | 分别用于开发和运行场景 |
| 底座 | 基础管理功能 | 用户、机构、权限、配置和审计功能 |
| 能力开放 | 对外提供服务 | 说明提供哪个接口、供谁使用 |
| 链路 | 数据传递过程、请求过程或部署路径 | 按具体过程表达 |
| 矩阵 | 表、清单或对照表 | 根据内容结构命名 |

## 保留的标准名称

- OpenAPI：用机器可读文件描述 HTTP 接口的国际通用规范，首次出现时说明用途。
- OAuth 2.0 和 OIDC：OAuth 2.0 用于授权，OIDC 是建立在 OAuth 2.0 之上的登录身份协议；仅在确实讨论认证方案时保留。
- SQL Server、PostgreSQL、Java、Vue、MyBatis、Maven、Node.js：软件或技术的正式名称，不改名。
- HTTP、HTTPS、REST、SOAP、JSON、XML、WSDL、TLS、CSRF、API：通用协议、格式或安全名称；在面向业务人员的文章首次出现时补充中文用途。
- Flyway、OpenAPI 文件中的 `schema`、Vue Router 代码中的 route/router：这些是第三方工具或正式文件结构中的固定名称，代码内部保留，页面和普通说明中改用易懂中文。
