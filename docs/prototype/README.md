# 县域接口平台双角色业务原型

## 工作台操作

原型首先呈现运行总览和待处理队列，而不是业务流程图。管理、运维通过右上角角色视角切换查看各自菜单；导航按工作台、配置管理、运行管理和安全审计分组，运维视角不显示配置管理组。总览指标进入相应列表。机构、接口、交换、异常、对账、告警和审计页面均以工作列表为主，可搜索或筛选并打开右侧详情抽屉。抽屉内用页签查看业务字段、处理轨迹和可执行的演示操作；按 Esc 或点击遮罩可关闭。

管理角色可新增和编辑合成机构配置，维护平台机构代码与外部机构代码的对应关系，并配置机构允许调用的接口和启停状态；还可维护接口版本、启停状态、编码对应和变更原因。运维角色可领取异常并登记核查结论、创建和执行对账任务、确认告警与登记恢复。结果未知时不得直接重发。所有操作保存在当前浏览器本地并进入审计记录；侧栏底部的重置按钮可恢复初始状态。

## 定位

原型入口：管理端 `/prototype`。用于业务、交互和权限评审；`DESIGN-*` 均为合成演示记录，不代表真实交换。县人民医院与基层卫生院是数据交换两端，不登录本平台。其诊疗、开单、报告审核和收费仍由各自原系统负责。本轮不设计工作站嵌入端业务页面，现有 `web-embed/` 工程骨架不作为本原型验收内容。

## 合成数据口径

演示数据位于 `web-admin/src/prototypeData.ts`，只由 `/prototype` 使用。示例县人民医院、示例青禾镇卫生院、`SIM-ORG-*`、`SIM-PAT-*`、`SIM-EHR-*`、`SIM-APPL-*`、`SIM-REQ-*`、时间与回执全部为虚构。没有真实患者姓名、证件号、手机号、报告正文、生产地址或凭证。接口代码、调用方向和字段概念参照现有接口矩阵与参考规范。页面统计只计算合成演示记录。

六笔演示记录覆盖上传超时未知、报告版本错配、机构越权拒绝、体检异步受理、LIS 报告明确回执、重复上传识别。相同源业务单号与请求编号贯通列表、详情、异常及对账页面，用来评审追踪方式。

## 两类角色

| 角色 | 可操作范围 | 不可操作范围 |
|---|---|---|
| 管理 | 机构配置、授权范围、接口台账版本与映射、接口启停配置；只读交换、异常、对账、告警和审计 | 代替原业务系统完成诊疗或修改交换结果 |
| 运维 | 运行总览、交换追踪、异常核查、对账执行、告警处置和授权范围内审计查看 | 修改机构权限、接口映射和接口启停；在结果未知时未经核查重复写入 |

管理端原型允许演示修改机构、接口和权限配置。所有本地配置、核查、对账和告警操作均不调用后端或触发真实交换。

## 业务与页面对应

| 业务链 | 原系统中的业务动作 | 平台管理视图 |
|---|---|---|
| 基础配置 | 维护机构、系统和业务编码 | 管理：机构代码、外部编码、接口权限和编码对应 |
| 健康档案与体检 | 原系统完成并审核记录 | 运维：受理、发送、明确回执、修改引用、对账 |
| 检查检验与心电 | 医技系统取申请单、审核报告并回写 HIS | 运维：申请单与报告版本校验、回写状态、异常追踪 |
| 结果未知 | 目标系统结果待查 | 运维：按业务单号核查目标状态或对账，记录结论；不直接重发 |
| 接口运行配置 | 按业务需要启用或停用接口 | 管理：维护接口版本、状态、编码对应和变更记录 |

页面导航为运行总览、机构与权限、接口与映射、交换记录、异常与处理、数据对账、告警管理、审计记录。运维角色不出现机构与权限、接口与映射入口；服务端正式实现仍必须独立校验权限，前端隐藏菜单不构成授权。

## 评审路径

1. 管理视角在“机构与权限”新增或编辑一个合成机构，维护外部机构编码和接口权限并保存。
2. 在“接口与映射”维护配置版本、启停状态和编码对应，填写变更原因后保存，并在变更记录和审计记录中核对结果。
3. 切换运维视角，通过 `DESIGN-04` 检查“已受理不等于处理成功”；打开 `DESIGN-01`，分别选择“目标已写入、明确未写入、仍无法确认”。明确结果需要填写回执编号或日志编号与备注。
4. 打开 `DESIGN-02`，选择重新校验、保持拦截或转入对账；重新校验不触发目标端再次写入，转入对账会生成对应任务。
5. 在“数据对账”按日期、机构和接口创建任务、执行并下钻差异，再到“告警管理”确认告警并登记恢复。
6. 在“审计记录”按主体和动作筛选，核对机构配置、接口变更、异常核查、对账和告警操作；刷新页面确认本地状态仍保留，使用“重置演示”恢复初始数据。

原型深度控制：机构、接口配置、异常、对账和告警做到可操作工作流级；交换记录和审计做到查询追踪级。原型以业务操作、状态反馈和页面联动是否完整作为评审标准，开发联调及上线条件另行管理。
