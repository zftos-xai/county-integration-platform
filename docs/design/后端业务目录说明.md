# 后端业务目录说明

## 1. 目的与适用范围

本文说明 `backend/src/main/java/cn/zqkj/platform` 下各目录的业务责任、放置规则和依赖边界。

目录按“谁拥有业务规则”划分，不按页面、数据库表或一次临时需求划分。一个类应只有一个归属；不能仅因某个流程会调用 HIS，就把平台业务模型、批次或 Mapper 放进 `his`。

本文覆盖 Java 源码与 MyBatis XML 的目录归属。具体命名、注释和分层要求以 [Java 与 AI Coding 规范](../standards/java-coding-guidelines.md) 为准。

## 2. 顶层目录

| 目录 | 主要责任 | 不负责 |
| --- | --- | --- |
| `common` | 跨业务且边界稳定的统一响应、异常、分页等基础类型；公共无状态工具统一经 `utils/Func` 调用 | 具体业务规则、HIS 协议、第二个通用工具入口 |
| `system` | 平台账号权限、机构、参数、字典、外部系统配置、管理审计与初始化 | HIS 报文、基础目录同步和交换记录 |
| `his` | 基层 HIS 的交易定义、请求校验、SOAP 通信、响应解析和协议错误归类 | 平台基础数据落库、批次状态和当前有效数据 |
| `masterdata` | 平台基础数据同步、校验、当前有效目录与同步批次记录 | SOAP 编解码、接口凭证解密、消费方读取实现 |
| `exchange` | 外部交互运行记录的查询与展示 | 发起 HIS 调用、写入基础目录 |
| `databasecontract` | 受控数据库契约检查、维护方案及其审计 | 一般业务数据 CRUD |
| `framework` | Spring 安全、配置、持久化及启动期技术装配 | 业务规则、领域模型、业务 Mapper |

## 3. 业务域与调用方向

```text
管理端 / 外部调用方
        │ HTTP
        ▼
业务域 Controller → 业务域 Service → Mapper（平台数据库）
                           │
                           ├─ system.configuration：解析机构专属 HIS 接口配置
                           └─ his：执行已确认的 HIS 交易并返回协议结果

masterdata：将 HIS 协议结果转换为平台基础数据和同步记录
```

允许的关键依赖：

- `masterdata` 的服务实现可以调用 `his` 的服务接口来取得已确认的交易结果。
- `his` 可以依赖 `system.configuration` 的接口配置解析能力，但不能依赖 `masterdata` 的领域对象或 Mapper。
- `system`、`exchange`、`databasecontract` 之间只通过明确的 Service 接口或稳定领域类型协作，禁止导入对方 `service.impl`。
- Controller 只依赖 Service 接口和本域 DTO/VO，不直接调用 Mapper、HIS Client 或其他域的实现类。

禁止的依赖：

- `masterdata/domain`、`masterdata/mapper` 导入 `his/domain` 的协议 DTO、响应或枚举。
- `his` 直接写入 `masterdata` 的当前目录表，或决定基础数据是否有效。
- 任何业务域导入 `system.*.service.impl`；审计通过 `ManagementAuditService` 接口调用。
- 把新的业务规则放进 `common` 或 `Func`；业务代码也不得绕过 `Func` 直接导入其内部分类工具类。

## 4. `system`：平台系统管理

`system` 是平台后台管理域，不是所有“系统相关”代码的收容目录。根目录不放 Controller、DTO、VO、Model、Mapper 或 Service 实现；文件必须进入以下一个子域。

| 子域 | 目录 | 负责的业务对象 | 典型内容 |
| --- | --- | --- | --- |
| 身份权限 | `system/identity` | 登录会话、用户、角色、权限、授权范围 | Session、User、Role、Access |
| 机构 | `system/organization` | 平台机构、启停状态、机构可见范围 | Organization |
| 配置 | `system/configuration` | 参数、字典、外部系统及机构专属接口配置 | Parameter、Dictionary、ExternalSystem、ExternalEndpoint |
| 审计 | `system/audit` | 管理操作审计事件与审计查询 | ManagementAudit |
| 初始化 | `system/bootstrap` | 初始化、平台基础状态与版本信息 | Bootstrap、PlatformInfo |

每个具有持久化能力的子域采用同一结构：

```text
system/<子域>/
├── controller/       # HTTP 协议入口
├── domain/
│   ├── dto/          # 请求、命令、查询条件
│   ├── model/        # 本域内部模型与持久化投影
│   └── vo/           # API 输出，名称以 VO 结尾
├── mapper/           # 仅 MyBatis Mapper 接口
└── service/
    └── impl/         # 业务规则、事务、审计与外部协作
```

`bootstrap` 当前没有数据库 Mapper 和复杂内部模型，只保留实际需要的 `controller`、`domain/dto` 与 `domain/vo`；不为“整齐”创建空包。

对应 XML 位于 `backend/src/main/resources/mapper/system/<子域>/`，并与 Mapper 接口按子域同名归属。

## 5. `his`：基层 HIS 协议适配

`his` 的边界是“按已确认协议把请求发出去并读回结果”。它不拥有平台基础数据，也不承担人工映射、发布或消费方校验流程。

```text
his/
├── client/                    # HTTP/SOAP 客户端与编解码
├── domain/
│   ├── protocol/              # 通用交易号、协议响应等稳定协议模型
│   ├── hospitaldirectory/     # 100-003 请求与返回模型
│   ├── medicaldirectory/      # 100-004、100-005 请求与返回模型
│   ├── organization/          # 100-008 请求与返回模型
│   └── endpointverification/  # 接口连通和配置校验所需模型
├── exception/                 # HIS 通信、协议、配置失败语义
└── service/                   # 面向业务域的受控交易入口及实现
```

放入 `his` 的判断标准：类的字段、校验或行为来自 HIS 协议，且脱离该协议就没有意义。例如 SOAP 参数、XML 编解码、交易码、返回行模型和通信异常。

不放入 `his` 的内容：平台目录记录、批次状态、平台 VO、平台 Mapper、当前有效数据失效策略。这些由 `masterdata` 负责。

## 6. `masterdata`：平台基础数据

`masterdata` 负责把已授权的 HIS 返回值转化为平台可查询的当前基础数据，并保留同步记录、校验结果和来源信息。当前业务按数据责任分为三个子域。

| 子域 | 目录 | 负责范围 |
| --- | --- | --- |
| 同步批次 | `masterdata/domain/batch`、`controller/batch`、`service/batch`、`mapper/batch` | 同步请求、范围、状态、来源与运行结果 |
| 医院综合目录 | `masterdata/domain/hospitaldirectory`、`controller/hospitaldirectory`、`service/hospitaldirectory`、`mapper/hospitaldirectory` | 100-003 科室、医生、病区、床位等当前有效数据和结果明细 |
| 医疗三大目录 | `masterdata/domain/medicaldirectory`、`service/medicaldirectory`、`mapper/medicaldirectory` | 100-004 / 100-005 药品、诊疗、耗材目录的取得、校验与对账 |

其层级规则为：

```text
masterdata/
├── controller/<子域>/
├── domain/<子域>/{dto,model,vo}/
├── mapper/<子域>/
└── service/<子域>/impl/
```

`masterdata` 的公开 DTO、Model、VO 和 Mapper 只能使用平台自己的类型。服务实现调用 HIS 后，应在该实现内把 HIS 协议返回值转换为本域模型；不能让 `his.domain.*` 穿透到 Mapper 或 API 输出。

对应 XML 位于 `backend/src/main/resources/mapper/masterdata/<子域>/`。

## 7. 其他业务与技术目录

| 目录 | 放置条件 |
| --- | --- |
| `exchange` | 仅与外部交互运行记录的读取、筛选、展示和关联有关时放入；它不替代协议 Client。 |
| `databasecontract` | 与数据库结构契约、扫描、维护计划、执行防护有关时放入；其审计只能依赖审计 Service 接口。 |
| `framework` | Spring 配置、安全过滤器、数据源、启动验证等技术装配；不得在这里新增业务 Controller、业务 DTO 或业务 Mapper。 |
| `common` | 只有被多个无直接业务依赖的域稳定复用，且不携带业务规则时才可放入。公共无状态工具统一使用 `Func.xxx()`；分类实现只在 `common/utils` 内部协作。新增前必须先证明不属于现有业务域。 |

## 8. 新文件归属检查

新增文件前依次回答以下问题：

1. 它的业务所有者是谁？是平台管理、HIS 协议、基础数据、交换记录还是数据库契约？
2. 它是 HTTP 输入输出、内部模型、数据库访问、业务规则还是技术装配？
3. 它是否含 HIS 协议字段或 SOAP 行为？若是，进入 `his`；若只是转换后的平台数据，进入 `masterdata`。
4. 它是否只属于 `system` 的一个子域？若是，进入对应子域，不得放到 `system` 根目录。
5. 它是否真的跨多个独立域且没有业务规则？只有同时满足才考虑 `common`；若是工具能力，必须由 `Func` 作为唯一调用入口。

无法明确回答第 1 题时，不新增文件；先补充业务边界或工程决策。

## 9. 自动约束与维护要求

- `tools/verify-java-package-layout.mjs` 校验 `system` 子域物理目录与包声明、禁止 `masterdata` 公开层导入 HIS 协议类型、禁止依赖其他系统子域的 `service.impl`，并禁止业务代码绕过 `Func` 直接调用内部分类工具类。
- `tools/verify-java-comments.mjs` 与 `tools/verify-mapper-comments.mjs` 校验 Java 和 MyBatis 注释要求。
- 本地提交前执行 `./tools/verify.sh`。目录调整必须同步移动 Mapper XML、测试、菜单交付清单和本文档。

本文描述的是当前已实现的目录边界，不表示已完成未取得证据的 HIS 联调、消费方读取或业务确认。
