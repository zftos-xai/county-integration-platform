# 县人民医院与基层卫生院中间接口平台项目立项书

> 文档版本：V0.2（立项评审稿）  
> 编制日期：2026年9月10日  
> 建设周期：2个月（完整交付）  
> 建设方式：院内私有化部署  
> 核心人员：5人

## 一、项目概况

### 1. 项目定位

建设一套部署在县人民医院指定环境内的中间接口平台，作为县人民医院与所辖基层卫生院之间的信息化连接枢纽，统一承接双方业务系统的数据交换、状态反馈、异常处理和运行管理。

本项目的业务协同主体只有县人民医院与所辖基层卫生院。平台只提供信息连接和运行保障，不增加新的业务层级，不替代双方进行诊疗、审核、收费、转诊决定或公共卫生管理。

### 2. 建设背景

双方已分别建设HIS、电子病历、检查检验等业务系统，但系统来源、接口形式和数据口径不同，仍存在对接入口分散、重复录入、信息错配、进度不可见、结果返回不及时、异常难处理和责任难定位等问题。由医院统一建设中间接口平台，可减少各厂商重复对接，形成统一入口、统一规则、统一记录和统一验收方式。

### 3. 周期与交付口径

项目建设周期为2个月，按8周组织实施。两个月为完整交付周期，包括平台建设、私有化部署、管理端和嵌入页面、立项范围内接口开发与联调、业务闭环验证、试运行、培训、文档移交和项目终验。

现有75项业务能力作为总体范围基线。接口是否启用及最终上线范围在项目启动阶段确认；尚不明确的接口全部列为P0事项，在项目早期集中解决，不得自然顺延到两个月以后。

|---|---|
| 《县人民医院与基层卫生院信息化协同对接方案》 | 项目需求、双方定位、协同范围和业务流程基线 |
| 《县人民医院与基层卫生院中间接口平台技术方案》 | 平台能力、私有化部署、技术方向和验收基线 |
| 《县级人民医院_基层和健康V1.0接口矩阵》 | 75项业务能力、调用方向、依赖、风险和验收要点盘点 |

## 二、项目需求与建设目标

### 1. 项目需求

本项目不是简单地“把两个系统连起来”，而是要让县人民医院与所辖基层卫生院形成可管理、可追踪、可验收的双向业务协作关系。相关平台和信息系统为双方协同提供技术支撑，但不增加新的业务层级。对接工作的核心，是明确双方哪些业务要协同、各自提供和使用什么信息、由谁负责、何时完成、出现问题如何处理，以及什么证据能够证明真正可用。

| 管理结论 | 建议 |
|---|---|
| 建设方式 | 由医院统一组织对接，各业务系统通过院内统一对接能力交换信息，避免各厂商各自建设、重复投入和责任不清。 |
| 范围口径 | 现有材料形成75项业务能力盘点，但这只是规划清单，不等于75项全部立刻建设，也不等于平台主管部门已全部批准。 |
| 推进顺序 | 先完成审批、责任、环境和基础信息准备，再推进健康档案、体检、检查检验报告等核心业务，随后分阶段扩展。 |
| 验收原则 | 以真实业务闭环和可复核记录为准，不以口头确认、页面能打开或单次调用成功作为完成依据。 |
| 上线原则 | 按业务领域分批试运行；任何患者错配、越权访问或无法确认的错误写入，都应立即停止相关写入。 |

“不等于75项全部立刻建设”是指按依赖和业务领域分批推进，不要求同时上线，不改变两个月内完整交付的要求。

项目建设要求如下：

- 确认首期建设范围：建议先做基础准备、健康档案与体检、检查检验与心电报告闭环。
- 确认项目牵头人、各业务领域负责人、厂商负责人和最终验收人。
- 确认平台主管部门负责提供正式接入文件、测试环境、账号授权及现有规范争议的书面结论。
- 确认电子病历回写是否纳入必做范围；现有清单写“不做”，但接口规范要求形成闭环。
- 确认生产上线采用分批试运行，并预留停止写入和恢复原流程的窗口。

### 2. 建设目标

| 当前问题 | 建设目标 | 预期成效 |
|---|---|---|
| 系统多、厂商多，问题发生后难判断责任归属 | 统一入口、统一台账、统一问题编号 | 问题能够定位到业务、系统、责任人和处理阶段 |
| 健康档案、体检和报告信息存在重复录入或回传不及时 | 业务完成后按规则自动交换并核对结果 | 减少重复操作，及时发现漏传、错传和重复 |
| 机构、人员、科室、诊断等基础信息口径不一致 | 建立统一映射并明确维护责任 | 降低人员、机构和患者匹配错误 |
| 部分业务依赖多个系统，单个接口成功仍无法完成全流程 | 按患者实际就医场景进行端到端验收 | 以挂号、就诊、报告、病历、转诊等完整结果判断成败 |
| 发生异常时缺少补救、对账和追踪手段 | 保留状态记录，支持核对、补偿和人工处理 | 避免重复收费、重复写入或长期积压无人处理 |

## 三、建设范围与接口计划

### 1. 双向协同范围

| 协同方向 | 主要交换内容 | 业务目的 |
|---|---|---|
| 基层卫生院到县人民医院 | 患者基本信息、基层诊疗摘要、转诊、检查检验、会诊申请及必要健康档案信息 | 让县医院提前了解患者情况并及时受理 |
| 县人民医院到基层卫生院 | 受理状态、预约或接诊安排、检查检验报告、诊疗建议、出院或转诊反馈、会诊结论 | 让基层及时掌握处理进度和结果 |
| 双方共同 | 统一机构、人员、科室、患者身份、目录、业务状态、问题编号和验收口径 | 保证业务对象正确匹配、过程和结果共同核对 |

居民和患者是双方共同服务对象，不是第三个协同主体。本期不建设基层卫生院之间的横向数据共享，不允许任何系统绕过统一入口直接访问另一方业务数据库。

### 2. 主要建设内容

- 中间接口平台后台服务、管理端及必要的独立或嵌入页面。
- 县医院HIS、电子病历、LIS、PACS与基层相关系统接口接入和转换。
- 机构、人员、科室、患者和业务编码对应关系管理。
- 数据接收、发送、防止重复、失败后再次处理、人工处置和数据对账。
- 机构、接口、权限、交换记录、问题、告警和统计管理。
- 私有化部署、SQL Server数据库、备份恢复、日志审计和安全防护。
- 接口文档、数据库脚本、部署运维手册、测试报告和验收材料。

平台不替代原业务系统，不建设新的完整病历数据库，只保存接口运行所需的必要记录和结果。

### 3. 接口范围与P0处理

现有接口矩阵共75项业务能力，其中健康档案云平台相关能力21项、基层侧相关能力54项，覆盖基础信息、健康档案、老年人健康、慢病、家庭医生、便民服务、双向转诊、电子病历、PACS、LIS、心电、分诊叫号、远程会诊和报告调阅等领域。

接口通知正文为“15类73个接口”，与75项业务能力矩阵存在交易码复用、补充能力和统计方式差异。截至当前材料，75项均为“未开始”，且存在待确认或前置条件，不代表已获接入批准或已完成真实联调。

| 优先级 | 处理范围 | 完成要求 |
|---|---|---|
| P0 | 接口数量、编号、地址、字段、成功结果、调用方向、业务是否启用、正式资料、环境和权限等不确定事项 | 第1至2周逐项取得书面结论，明确责任人和截止时间，不得自然顺延 |
| P1 | 审批、机构人员、科室目录、患者匹配、权限、安全、环境和平台共同基础 | 第1至3周完成，为全部接口提供基础 |
| P2 | 立项范围内各业务接口开发、厂商改造、联调和业务闭环 | 第3至7周按业务领域并行完成 |
| P3 | 全量回归、安全性能检查、试运行、资料移交和终验 | 第7至8周完成完整交付 |

每项接口进入联调前必须具备正式接口文件、测试环境、访问凭证、脱敏样例、调用规则、责任人和验收场景。

## 四、总体建设方案

### 1. 平台结构

`基层卫生院业务系统 ⇄ 中间接口平台 ⇄ 县人民医院HIS、电子病历、LIS、PACS等系统`

平台统一完成身份验证、数据检查、格式转换、防止重复、故障处理、过程记录和运行管理。双方原有系统继续负责业务办理和数据维护。

### 2. 技术与部署

| 项目 | 建议选择 | 说明 |
|---|---|---|
| 后台服务 | Java 21、Spring Boot 3.5、MyBatis | 建设一套后台应用，后续具备条件时独立升级Spring Boot 4 |
| 数据库 | Microsoft SQL Server 2019/2022 | 以医院现网支持版本为准，建立独立平台数据库和账号 |
| 管理页面 | Vue 3、TypeScript | 管理机构、接口、运行记录、异常和配置 |
| 嵌入页面 | 网页组件或嵌入页面 | 根据HIS和基层工作站浏览器环境确定 |

后台、数据库、管理页面和日志全部部署在医院本地机房或私有云。测试、联调和生产环境分开；除正式接口要求外，不向外部厂商同步患者数据、日志或备份；外部厂商远程访问须经医院审批并留痕。

平台可复用HIS所在SQL Server服务器，但必须使用独立数据库、账号、备份和维护计划，不在HIS业务库中建立平台表。读取HIS数据优先采用厂商正式服务；确需只读视图时，由医院和HIS厂商共同确认。

### 3. 安全与运行保障

- 按人员、机构和职责授权，基层卫生院只能访问本机构获准数据。
- 账号、密钥、验证码等由平台统一保管，不存放在客户端或普通日志中。
- 优先使用医疗专网；互联网访问须审批并采用HTTPS和固定来源限制。
- 仅交换业务必需数据，敏感信息按权限隐藏，查询、导出和配置变更可追溯。
- 接口失败、凭证失效、待处理积压、数据不一致和异常访问及时告警。
- 数据库、配置和必要文件按医院制度备份，并定期验证恢复能力。

## 五、人员安排与职责

### 1. 核心团队

项目核心实施团队按5人配置：

| 工作组 | 人数 | 主要职责 | 主要交付 |
|---|---:|---|---|
| 县人民医院HIS改造组 | 2人 | 主要负责核心业务、HIS数据提供、接口和页面改造、结果展示及联调处理 | HIS改造、数据服务或受控视图、业务入口、结果回写和测试记录 |
| 中间接口平台组 | 2人 | 负责平台后台、管理端、嵌入页面、接口转换、异常处理、对账、部署和文档 | 平台系统、约定接口接入、部署制品、数据库脚本和技术资料 |
| 项目对接与协调 | 1人 | 负责范围、P0问题、跨方协调、计划、会议、材料、培训和验收 | 项目计划、P0清单、问题台账、周报、培训和验收材料 |
| 合计 | 5人 | 按业务领域并行推进 | 两个月内完成建设、联调、试运行和验收 |

HIS组和平台组各自明确主责与备份，核心人员在两个月内保持稳定。项目对接人员不替代开发人员。基层卫生院、电子病历、LIS、PACS、网络安全和接口提供方仍需各自指定配合联系人，不计入核心5人。

### 2. 协同职责

| 参与方 | 主要职责 |
|---|---|
| 医院项目负责人 | 决定目标、范围、资源和重大事项，组织验收和上线决策 |
| 医院信息科及业务科室 | 牵头协调，确认流程、数据口径、样例、权限和验收结果 |
| 医院安全与运维 | 落实网络、安全、账号、监控、备份和值守 |
| 基层卫生院 | 确认实际需求、使用入口和人员权限，参与联调及验收 |
| HIS及相关系统厂商 | 提供正式资料，完成系统改造，配合联调和问题修复 |
| 平台主管或接口提供方 | 提供接入授权、正式资料、测试条件和争议书面结论 |

每项任务只设置一个执行责任方和一个验收责任方。没有负责人、完成时间和验收证据的任务，不计入完成范围。

| 第2至3周 | 完成平台、数据库、权限、管理端框架和私有化测试环境 | 平台组主责，HIS组准备数据和入口 | 可运行的平台基础版本 |
| 第3至6周 | 并行完成全部约定接口开发、厂商改造和联调 | HIS组负责核心业务，平台组负责平台与接口 | 接口完成清单、测试记录和问题关闭记录 |

两个月完整交付要求5名核心人员按时到位、范围第1周冻结、正式资料和环境第2周具备、各厂商并行配合、P0问题每日跟踪并及时升级。P0事项未按期关闭时，由项目负责人协调处理；未经正式范围变更，不得自行移出本期，也不得降低安全或验收标准。

## 七、投入、效益与风险

### 1. 投入原则

项目预算根据完整接口范围和实际改造量另行测算，主要包括平台软件、HIS及相关系统改造、服务器和SQL Server资源、网络安全、实施联调、培训验收及运维保障。不能仅按75项数量简单平均估算工作量。

### 2. 预期效益

- 县人民医院统一受理和管理基层协同事项，提前获得必要信息并及时反馈结果。
- 基层卫生院在原有工作入口发起业务、查看进度并获得报告或诊疗反馈。
- 减少患者重复提供资料、重复检查和不必要往返，提高县域资源使用效率。
- 从多厂商分散对接转为统一管理，每笔交换可查询、问题可定位、结果可核对。
- 系统和数据在医院指定环境中私有化部署，权限、凭证和操作记录集中管理。

### 3. 主要风险

| 风险 | 应对措施 |
|---|---|
| 两个月完整交付压力较大 | 固定5人核心团队，按业务领域并行开发，实行周计划和P0日跟踪 |
| 通知73个接口与矩阵75项口径不一致 | 列为P0，由平台主管部门和厂商第2周前提供书面结论 |
| 正式接入、环境或凭证未准备 | 列为P0，第1至2周集中关闭并由项目负责人升级协调 |
| 多厂商配合延迟 | 明确责任人、完成时间和问题升级路径，相关厂商指定固定联系人 |
| 基础信息不一致 | 先完成机构、人员、科室和患者对应关系及脱敏抽样核对 |
| 写入结果不明确 | 先查询和对账，禁止直接重复写入或重复收费 |
| 平台影响HIS运行 | 独立数据库和账号，限制连接和批量任务，完成性能测试 |
| 敏感数据泄露 | 私有化部署、最小权限、传输保护、信息隐藏和操作审计 |

## 八、验收与立项建议

### 1. 验收标准

- 平台已在医院指定环境完成私有化部署。
- 立项范围内接口和完整业务闭环全部完成，状态及结果能够双向反馈。
- 双方关键患者、机构、业务单号、申请内容和结果抽样一致。

- 不同机构和角色不能访问未授权数据；每笔业务可查询、失败可定位、数据可对账。
- 安装包或约定制品、数据库脚本、配置、接口、部署运维和测试文档齐全。
- 业务科室、信息科、安全运维和项目负责人完成书面确认。

存在患者错配、越权访问、敏感信息暴露、写入结果无法确认、问题不可追踪、恢复方案未验证，或正式接入及生产安全条件未满足时，不得通过上线验收。

### 2. 立项审批建议

建议批准：

1. 建设县人民医院与基层卫生院中间接口平台，并采用院内私有化部署。
2. 建设周期为2个月，完成立项范围内全部建设、联调、试运行、移交和终验。
3. 核心团队按5人配置：县人民医院HIS改造2人、中间接口平台2人、项目对接与协调1人。
4. 第1周冻结完整范围和验收标准，全部不确定接口列为P0并明确关闭期限。
5. 同步启动正式接入申请、网络安全评审、环境、凭证及相关厂商配合安排。
6. 按完整范围、厂商改造量、并行人员和基础设施复用情况形成专项预算。
