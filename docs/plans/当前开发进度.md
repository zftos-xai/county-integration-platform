## 六、基础数据真实状态与下一里程碑

当前代码和数据库处理过程已覆盖“选择服务地址 → 创建批次 → 用100-007核对数量 → 用100-006分页取得数据 → 检查字段、重复和冲突 → 保存结果 → 发布本次目录或保留上一批成功结果 → 查询批次详情、HIS调用记录和审计记录”。这证明开发中的处理过程可以运行，不证明当前测试地址已经提供可发布的完整 ICD-10 目录。

已知同步情况：测试地址曾返回西医 36,647 条、中医 2,653 条，但部分记录字段不符合规则，并存在重复记录及同类别同编码冲突。因此批次保持 `FAILED` 或 `COMPLETED_WITH_UNKNOWN`，`md_icd10_diagnosis` 未发布不完整数据。该结论来自受控测试地址和开发数据库重新查询；不得用手工改表、修改 Flyway 历史或跳过校验替代新批次。

下一里程碑按以下顺序执行：

1. 由环境负责人配置获批的 HIS 测试端点和凭证，并显式开启真实探测；不在文档或前端保存敏感值。
2. 选择一个测试机构，先执行 100-007，再执行 100-006 分页同步，记录批次状态、声明数量、取得数量、拒绝原因和当前目录数量。
3. 从页面复核批次详情的目录结果、HIS调用记录和审计记录；从 `/master-data/directory/icd10` 复核当前有效数据、分类查询和最近批次追溯。
4. 补齐失败、结果未知、无权限、跨机构和重复提交场景；确认失败不覆盖上一成功目录，结果未知不自动重发。
5. 当前证据只覆盖技术同步、数量核对和目录发布；实际使用目录的业务页面读取及业务使用情况尚无记录。后续如需评估业务可用性，应先明确实际使用范围和核验方法，再据实更新状态；目前不记录签收或业务验收结论。
