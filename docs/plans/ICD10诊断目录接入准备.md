# ICD10 诊断目录接入准备

状态：已确认按平台公共目录管理，不设置机构业务归属；接口资料仍在核对中，尚未批准进入来源同步编码或真实 HIS 调用。

本文为 `100-007` 行数查询与 `100-006` 分页查询建立开发前契约，不将接口文档的示例值、现有三大目录实现或交易码登记视为联调证据。接口开发前的通用放行条件另见 [单个接口开发前检查表](../../interface-specs/接口开发前检查表.md)。

## 1. 已有依据与当前代码边界

- 上游文档的 6.1.6、6.1.7 节分别定义 `100-006`、`100-007`。`PhisTrade` 已登记交易码，但 `PhisService` 尚无诊断查询方法；`MasterDataCategory` 只开放医院综合目录和药品、诊疗、耗材目录，不能把交易码登记等同于可执行同步业务。
- 最新接口清单将 `100-006` 关联到 `基卫_诊断数据`；诊断目录按实际业务作为平台公共目录，不设置机构业务归属。其对象类型、读写方向、字段、授权及县医院 HIS 的消费方式尚待确认。
- 当前批次表虽预留 `diagnosis_category`、`diagnosis_version`，现有创建请求、运行分派、诊断目录表、结果查询和正式页面均未形成闭环。预留列不等于诊断目录模型已确定。
- 三大目录的分页、交换记录、分项提交和结果未知处理可借鉴行为边界；ICD10 的范围、编码键和版本不能复用三大目录的业务假设。当前工作区另有医疗目录同步改动，实施 ICD10 前应先取得稳定且通过 `./tools/verify.sh` 的基线。

## 2. 从上游文档直接可读的字段

| 交易 | 请求条件 | 响应事实 |
| --- | --- | --- |
| `100-007` 行数 | 验证码；可选病种名称；必填开始/结束时间；可选疾病类别、诊断版本 | 示例含行数；详细表另列“目录名称”，与示例不一致，须用脱敏真实响应确认 |
| `100-006` 数据 | 与行数查询相同的筛选条件，另有必填开始/结束行数 | 必填病种编码、病种名称、创建时间；可选助记码、备注、疾病 ID |

文档将疾病类别写为 `0` 西医诊断、`1` 中医诊断、空值为全部；诊断版本未标为必填，仅举例“病案直报系统”“医保国临版”，且单条响应并不返回版本字段。因此版本只能作为可选查询条件和批次追溯事实，不能预设为目录强制层级或由平台生成“默认版本”。在无版本来源场景，调用不传版本条件，页面不展示版本切换或版本列；同步详情明确记录“来源未提供”。`100-006/100-007` 请求均未列机构编码，因此诊断目录不设置机构业务归属，也不沿用 `100-004/100-005` 的平台机构编码传参。

## 3. 编码前必须关闭的业务与协议问题

| 问题 | 需要的确认结果与证据 |
| --- | --- |
| 来源与使用范围 | HIS 提供方、诊断数据实际维护方及 `基卫_诊断数据` 的对象类型与消费方读取契约；目录已确认全县共用，不再确认或设计按机构隔离 |
| 首批类别与版本 | 首批是只接西医、只接中医还是两者；是否实际传递版本条件。仅在来源返回或业务方确认非空版本字符串时，才确认版本归属、切换及同编码跨版本处理；否则固定为无版本模式 |
| 稳定业务键 | 病种编码是否在首批实际查询范围内唯一、疾病类别是否需要参与键、疾病 ID 的稳定性及可空情况、重复编码与同码不同名的处理依据；不得在资料核对阶段预设“类别 + 版本 + 编码” |
| 时间范围 | 上游过滤的是创建、修改还是其他时间；边界是否包含端点、时区、无时间记录及历史覆盖起点；不能套用三大目录的“近 20 年”约定 |
| 行数和分页 | 行号从几开始、结束行是否包含、单次最大行数、排序是否稳定；同条件 `100-007` 声明数与 `100-006` 全部页面能否核对，以及查询期间变化的处理 |
| 成功和失败 | 实际成功码、空结果、业务失败、超时和已接收但无法解析响应的脱敏样例；`100-007` 结果中“目录名称”是否存在 |
| 停用与缺失 | 是否有停用/删除字段或事件；若无完整来源快照证明，未返回记录不得自动失效或删除 |
| 责任与验收 | 业务负责人、HIS 技术联系人、县医院 HIS 消费方和验收负责人；测试机构/环境、授权及脱敏样例存放位置 |

任一问题未关闭时，保持“接口资料不完整”；可继续做资料核对和无写入的协议探测设计，不注册可执行 ICD10 同步类别，不创建空批次或模拟成功页面。

## 4. 拟实施的调用链与边界

1. `Controller` 沿用批次创建、执行和读取入口的功能权限检查。诊断目录查询使用公共目录读取权限，不按机构筛选；为调用 HIS 而选择的受控端点仅是运行配置和追溯事实，不得成为诊断记录的机构归属。批次执行仍须限制为有权使用该端点的范围。
2. `Service` 在创建时固化类别、可选版本、时间范围、来源端点和请求标识；无版本来源将版本保存为空并在调用时不传该条件。执行前验证来源未变化，使用数据库状态取得唯一执行权。外部调用不得包在数据库事务内，重复执行和旧版本提交须在调用前拒绝。
3. `his` 域新增 `100-007` 数量及 `100-006` 分页的强类型请求和响应模型；验证码只由受控运行配置装配。两次交易必须使用同一组类别、可选版本、病种名称及时间条件，所有页面复用批次冻结的条件。
4. 每次计数与分页调用分别记录脱敏交换事实。仅在全部页面可解析、声明数与实际返回数一致、必填字段及业务键校验通过后，才对该已确认范围执行幂等写入；失败或结果未知保留原目录，不自动重发，也不依据缺失使旧数据无效。
5. 目录查询、批次分项结果、页面和 OpenAPI 随已确认的数据归属设计同步完成。输出应能说明类别、版本（如来源提供）、来源、范围、取得/新增/更新/未变化数量与失败原因；无版本时不展示版本控件或版本列，只在同步详情记录来源未提供；不提供修改 HIS 来源数据的页面。

新增诊断领域模型的理由是现有药品/诊疗/耗材类型无法准确表达疾病类别、可选诊断版本、病种编码和可选疾病 ID。批次操作仍复用现有入口与状态机，不另建平行批次系统；诊断目录唯一键必须以真实响应验证后的稳定来源键为基础，不含机构，不能在开发前用假定的类别、版本组合代替确认。SQL 变更须遵守 SQL Server 2012 SP4、兼容级别 110 及项目迁移版本规则。

## 5. 最小验证与验收证据

- 使用获准测试环境做**只读**协议探测：同条件计数、首页/末页、零行、类别与空版本条件；仅在来源确认版本值后再验证类别与版本组合。记录脱敏请求条件和响应结构，不保存验证码或完整敏感报文。探测不写平台正式目录，也不把样例范围称为全量。
- 自动化覆盖无权限/跨范围、同请求重复、旧版本、分页缺页与重页、声明数不一致、同码冲突、可选疾病 ID 缺失、超时/结果未知、明确失败、零行和第二次幂等同步。
- 在归属及存储模型确认后，按已批准范围完成真实同步、SQL Server 2012 回读、正式页面回读、消费方只读读取和数量核对。业务负责人确认类别、版本、编码和实际使用结果后，才按统一业务完成标准标记为通过。
