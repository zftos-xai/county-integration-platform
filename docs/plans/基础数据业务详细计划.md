# 基础数据业务详细计划

版本：1.0
制定日期：2026-09-18
当前状态：BD-00进行中；实际WSDL和离线SOAP编解码已验证，真实`100-001/100-002`调用尚未完成

本文细化“第二优先：完成基础数据业务”，覆盖基层基础数据从来源系统取得、平台保存、停用处理、数量核对和县医院 HIS 只读查询的完整业务过程。本文不把旧平台配置、接口文档示例或空结果视为真实联调完成证据。

## 1. 目标和完成结果

基础数据业务按以下顺序完成：

1. 确认接口入口、调用身份和机构对应关系。
2. 完成机构数据。
3. 完成科室、病区、人员和床位数据。
4. 完成中药、西药、诊疗和耗材目录。
5. 完成已确认需要接入的疫苗、血液目录。
6. 完成 ICD10 诊断目录。
7. 确认公共字典的真实来源后再安排开发。
8. 为每类已完成数据提供县医院 HIS 只读视图并完成三方数量核对。

最终应能由业务人员说明：

- 数据由哪个系统负责维护。
- 平台通过哪个接口取得哪些数据。
- 平台保存和停用哪些记录。
- 县医院 HIS 能够读取哪些字段和记录。
- 数据重复、缺失、失败和数量不一致时如何处理。
- 谁确认来源结果、平台结果和 HIS 读取结果。

## 2. 当前已有依据

### 2.1 已有接口资料

基层系统统一通过 WebService 的 `PHIS_Interface` 入口调用，一级参数为 `TradeCode` 和 JSON 格式的 `InputParameter`，公共响应使用 `result/msg`或`Result/Msg`表达业务结果。基础数据涉及：

| 接口 | 业务用途 |
| --- | --- |
| `100-001` | 接口连通检查 |
| `100-002` | 登录验证并取得验证码 |
| `100-003` | 查询科室、医生、病区和床位综合目录 |
| `100-004` | 分页查询中药、西药、诊疗、耗材、疫苗和血液目录 |
| `100-005` | 查询上述目录在指定条件下的行数 |
| `100-006` | 分页查询 ICD10 诊断目录 |
| `100-007` | 查询 ICD10 诊断目录行数 |
| `100-008` | 查询医疗机构信息 |

具体字段和原始示例以[新版基层HIS与云平台接口文档](../reference/interfaces/新版基层HIS%20与云平台V1.0接口文档.md)为依据，但文档中的名称大小写、接口入口和部分字段说明存在冲突，必须用实际 WSDL 和脱敏响应样例确认。

### 2.2 已取得的实际配置线索

已从其他平台数据库取得一条机构级接口配置样本，能够证明现有环境中存在以下信息：

- 基层机构来源标识。
- `PHIS_Interface`服务地址。
- 厂商编号和 HIS 验证码相关字段。
- HIS 验证码有效期字段。
- 健康档案云、EHR、LIS、PACS 和支付等其他系统配置字段。

该样本只用于确认字段来源和准备联调，不直接复制到本平台。明文密码、Secret、验证码、账号和完整连接值不得写入本文、业务表、日志或测试证据；调用程序只从批准的凭证来源取得所需值。

基层HIS配置按“外部系统 + 部署环境 + 平台机构”唯一保存。即使多个机构共用同一WebService地址，也必须各自保存一条机构级配置，并各自指向本机构的凭证引用。运行时必须按当前机构精确解析，不允许回退到其他机构或全局验证码。

### 2.3 已确认的数据传递过程

```text
基层系统
  → 100-001至100-008基础数据接口
  → 中间接口平台检查并保存
  → 平台库受控只读视图
  → 县医院HIS读取
  → 来源数量、平台数量和HIS读取数量核对
```

县医院 HIS 不写入平台基础数据表。平台系统字典只用于平台自身状态和页面展示，不保存药品、诊疗、耗材、人员或诊断目录。

## 4. 统一业务规则

### 4.1 来源和唯一标识

每条基础数据至少记录：

- 数据类别。
- 来源系统。
- 来源机构标识。
- 来源记录标识。
- 来源创建时间或版本；接口没有提供时明确记为“来源未提供”。
- 平台首次取得时间和最后一次取得时间。
- 当前有效状态。
- 最近成功同步批次。
- 最近核对结果。

暂定唯一识别规则如下，必须在首批真实样例到达后复核：

| 数据类别 | 暂定唯一识别规则 |
| --- | --- |
| 机构 | 来源系统 + `100-008.ID` |
| 科室 | 来源系统 + 机构ID + 目录类型 + 目录编码 |
| 人员 | 来源系统 + 机构ID + 目录类型 + 目录编码 |
| 病区 | 来源系统 + 机构ID + 目录类型 + 目录编码 |
| 床位 | 来源系统 + 机构ID + 目录类型 + 目录编码 |
| 中药、西药、诊疗、耗材、疫苗、血液 | 来源系统 + 机构ID + 目录类型 + 目录编码 |
| ICD10诊断 | 来源系统 + 诊断版本 + 疾病类别 + 疾病编码 |

不能使用名称作为唯一标识。上游机构ID只用于来源映射，不直接覆盖平台机构代码、机构层级或用户权限范围。

### 4.2 新增、更新和重复

- 唯一标识不存在时新增。
- 唯一标识已存在且业务字段发生变化时更新。
- 同一批次重复返回同一唯一标识时，不生成重复记录，记录重复数量并按已确认规则选择结果。
- 同一唯一标识出现互相冲突的名称、归属机构或关联编码时，该批次对应记录进入待核查，不静默覆盖。
- 再次执行同一查询范围不得产生重复业务记录。

### 4.3 停用和来源缺失

- `100-004`返回的“是否启用”只有在取值含义确认后才能转换为平台有效状态。
- `100-003`、`100-006`和`100-008`没有明确停用字段，单次未返回不能直接停用。
- 全量批次发现历史记录缺失时，先标记为“来源缺失待核查”。
- 只有来源系统负责人确认缺失表示停用或删除后，平台才按该类别的已批准规则停用。
- 已被历史业务引用的数据不得物理删除；停用后仍允许历史查询，但不得用于新的业务。

### 4.4 失败和结果未知

- `result/Result`明确为失败时，保存接口返回的可理解失败原因和请求编号，不改变上一成功批次的数据。
- 网络中断、超时或响应无法解析时，记录为“结果未知”，不把本次范围内原有数据停用。
- 分页过程中部分页面失败时，整个批次不发布为当前成功版本；保留失败页范围供继续处理。
- 行数接口与实际分页累计数不一致时，不发布该批次，重新核对相同查询条件。
- 空结果必须区分“来源确认确实为空”和“接口异常导致为空”。

### 4.5 数量核对

每类数据至少形成以下数量：

| 数量 | 含义 |
| --- | --- |
| 来源声明数 | 行数接口返回值；没有行数接口时由来源负责人确认 |
| 来源实际返回数 | 本批次各页成功返回的记录总数 |
| 来源去重数 | 按该类唯一标识去重后的记录数 |
| 平台新增数 | 本批次新增记录数 |
| 平台更新数 | 本批次修改记录数 |
| 平台未变化数 | 已存在且内容未变化的记录数 |
| 平台冲突数 | 唯一标识相同但关键关系冲突的记录数 |
| 平台待核查缺失数 | 上次存在、本次未返回且不能直接停用的记录数 |
| 平台有效数 | 当前允许用于新业务的记录数 |
| HIS视图读取数 | 县医院HIS使用只读账号按相同范围读取的数量 |

核对范围必须同时注明机构、数据类别、目录类型、时间范围、诊断版本、疾病类别和批次号，不能只比较三个没有范围说明的总数。

## 5. 分项开发计划

### 5.1 BD-00：确认调用入口和身份

#### 输入

- 接口规范中的 WebService 和`PHIS_Interface`说明。
- 已取得的其他平台机构级配置样本。
- 基层系统厂商提供的实际 WSDL、测试地址和授权说明。

#### 处理步骤

1. 核对实际方法名是`PHIS_Interface`还是其他名称。
2. 核对正式交易码是否为`100-001`至`100-008`，不使用文档示例中的缩写交易码。
3. 确认厂商编号由谁分配、适用哪个环境和机构。
4. 确认`100-002`是否允许后台同步任务使用，以及验证码有效期、失效结果和重新取得方式。
5. 取得`100-001`和`100-002`的脱敏正常、失败、超时和无效凭证样例。
6. 确认调用成功时实际使用`result/msg`还是`Result/Msg`，以及字段类型是数字还是字符串。

#### 输出

- 一份不含明文凭证的调用参数说明。
- 一组脱敏的正常和失败响应样例。
- 确认后的成功、失败、超时和结果未知判断规则。

#### 完成标准

能够用获准测试身份完成一次`100-001`连通检查和一次`100-002`验证，并能区分成功、业务失败、无响应和响应格式错误。

### 5.2 BD-01：机构数据

#### 接口和字段

使用`100-008`。主要返回字段为机构ID、医院名称、地址、联系电话、邮政编码和联系人，其中机构ID供其他接口作为机构编码使用。

#### 处理步骤

1. 使用空医院名称或厂商确认的全量条件取得机构列表。
2. 校验机构ID和医院名称必填。
3. 按“来源系统 + 机构ID”去重。
4. 建立上游机构与平台机构的受控映射。
5. 对重复ID、同名不同ID、同ID不同名称和未映射机构分别记录结果。
6. 接口没有更新时间和停用状态时，采用全量快照核对，缺失记录进入待核查。
7. 与县医院 HIS 确认机构视图的最小字段和过滤范围。
8. 完成来源实际返回数、平台数和HIS视图读取数核对。

#### 异常处理

- 机构ID缺失：拒绝该条记录并记录字段错误。
- 机构名称缺失：拒绝该条记录并记录字段错误。
- 同一机构ID返回多个名称：进入冲突待核查。
- 上游机构未映射：可以保存来源记录，但不得自动取得平台机构权限或用于正式视图。
- 本批次未返回历史机构：不得自动停用。

#### 完成标准

至少一个真实非零机构完成“来源查询—平台保存—平台机构映射—HIS只读查询—数量核对”，并由来源负责人、平台负责人和HIS验收人共同确认。

### 5.3 BD-02：科室和病区数据

#### 接口和字段

使用`100-003`：

- 目录类型`0`查询科室。
- 目录类型`2`查询病区。

公共字段包括目录编码、目录名称、助记码、目录类别名称和备注。

#### 处理步骤

1. 仅对已经完成映射的机构执行查询。
2. 分机构、分目录类型取得数据。
3. 校验目录编码和目录名称。
4. 按机构和目录类型分别去重，不能将病区作为科室保存。
5. 保存来源批次和最后取得时间。
6. 没有分页和数量接口时，由来源负责人确认预期数量或提供数据库侧核对数。
7. 单次缺失只进入待核查，不自动停用。
8. 分别提供科室和病区HIS只读视图及数量核对结果。

#### 完成标准

每个首批机构的科室和病区均能按编码稳定读取；重复编码、空编码、同码异名和来源缺失都有明确处理结果。

### 5.4 BD-03：人员和床位数据

#### 接口和关系

使用`100-003`：

- 目录类型`1`查询医生或医护人员。
- 目录类型`3`查询床位。

人员可能包含科室编码、科室名称、机构编码、国家医保编码、账号、执业证书、资格证书、人员类别、医护类型、职称、电话和性别。床位通过文档中的备注字段关联病区，但该关系必须用实际样例确认。

#### 处理步骤

1. 先完成机构、科室和病区同步。
2. 确认目录类型`1`代表医生还是全部医护人员，并明确首批人员范围。
3. 确认人员所属科室以“备注”还是“科室编码”为准。
4. 确认一名人员是否可能属于多个科室。
5. 只保存业务所需且已批准的人员字段，不默认保存身份证、照片和联系电话。
6. 不能关联到已知科室的人员进入待核查，不自动建立虚假科室。
7. 确认床位所属病区字段；不能关联的床位进入待核查。
8. 完成人员和床位来源数、平台数和HIS读取数核对。

#### 完成标准

人员能够按来源机构和科室正确关联，床位能够按病区正确关联；不会把同名人员合并，也不会把其他机构人员挂到当前机构。

### 5.5 BD-04：药品、诊疗、耗材、疫苗和血液目录

#### 接口和类型

先调用`100-005`取得行数，再调用`100-004`分页取得数据：

| 目录类型 | 数据类别 | 首批处理 |
| ---: | --- | --- |
| `0` | 中药 | 纳入 |
| `1` | 西药 | 纳入 |
| `2` | 诊疗 | 纳入 |
| `3` | 耗材 | 纳入 |
| `5` | 疫苗 | 业务方确认后纳入 |
| `6` | 血液 | 业务方确认后纳入 |

#### 处理步骤

1. 确认开始行数、结束行数的边界是否包含端点，以及单页最大行数。
2. 对同一机构、目录类型、名称条件和时间范围先调用`100-005`。
3. 固定查询条件后分页调用`100-004`，不能在一个批次中改变时间范围。
4. 校验目录编码、目录名称、目录类别名称和创建时间。
5. 按“来源系统 + 机构 + 目录类型 + 目录编码”去重。
6. 核对行数接口结果、分页累计数和去重数。
7. 确认“是否启用”的字段类型和取值后再处理停用。
8. 确认时间范围按创建时间还是更新时间过滤；确认前仅将其作为查询条件，不作为可靠增量依据。
9. 分目录类型提供HIS只读视图和核对结果。

#### 异常处理

- 行数大于零但分页返回空：批次失败。
- 分页累计数与行数不一致：批次不发布，按相同条件重新核对。
- 页间重复：去重并记录重复数；超过允许范围时批次待核查。
- 目录编码相同但类型不同：分别保存，不跨类型覆盖。
- “是否启用”无法识别：保留原值并进入待确认，不自行转换。

#### 完成标准

中药、西药、诊疗和耗材分别完成至少一次非零全量取得、分页核对、平台保存和HIS读取；疫苗、血液明确纳入或不纳入及原因。

### 5.6 BD-05：ICD10诊断目录

#### 接口和范围

先调用`100-007`取得行数，再调用`100-006`分页取得数据。查询范围包括：

- 疾病类别：西医诊断、中医诊断或全部。
- 诊断版本：病案直报系统、医保国临版或厂商确认的实际版本。
- 开始时间和结束时间。

#### 处理步骤

1. 由业务方确认需要支持的疾病类别和诊断版本组合。
2. 每个组合独立查询行数、分页取得和核对。
3. 校验疾病编码、疾病名称和创建时间。
4. 确认疾病编码与疾病ID哪个是跨批次稳定标识。
5. 按暂定组合键去重，版本之间不得互相覆盖。
6. 确认时间过滤含义；未确认前按全量批次验收。
7. 对停用、删除和版本废止建立业务确认规则。
8. 提供县医院 HIS 诊断目录只读视图和分版本数量核对。

#### 完成标准

每个已确认的疾病类别和诊断版本都能独立完成行数查询、分页读取、平台保存和HIS读取核对，不发生跨版本覆盖。

### 5.7 BD-06：公共字典

当前接口资料没有提供通用公共字典查询接口，不能根据平台系统字典或接口中的固定枚举虚构同步来源。

开始开发前必须形成公共字典清单，每项至少确认：

- 字典名称和业务用途。
- 负责维护的系统。
- 取得方式和字段。
- 字典项编码、名称、排序和启停含义。
- 是否按机构区分。
- 历史业务引用后的停用规则。
- 县医院 HIS 是否需要读取及读取字段。

完成标准：业务方明确每类公共字典的来源和用途；没有正式来源的字典继续保持“接口资料不完整”，不进入开发完成统计。

### 5.8 BD-07：HIS只读视图和最终核对

每类数据完成平台保存后，分别与县医院 HIS 厂商确认：

- 视图用途和消费系统。
- 最小字段、字段类型和空值规则。
- 机构过滤范围。
- 是否只返回有效数据。
- 查询频率、单次数据量和排序要求。
- 视图版本和兼容期。
- 数量核对语句和核对范围。

每个视图必须引用某个已成功发布的数据批次。失败、部分成功、结果未知和待核查批次不能成为当前HIS读取版本。

完成标准：县医院 HIS 使用只读账号读取非零真实数据，读取数量与同范围的平台有效数量一致，并由HIS验收人确认字段可用。

## 6. 统一验收场景

每类基础数据至少执行以下场景：

1. 正常取得非零数据并保存。
2. 必填代码或名称缺失。
3. 同一批次出现重复记录。
4. 已存在记录内容发生变化。
5. 同一标识出现关键关系冲突。
6. 来源返回明确失败。
7. 网络超时或结果未知。
8. 来源返回空结果。
9. 全量批次发现历史记录缺失。
10. 分页中某一页失败。
11. 行数接口与分页累计数不一致；没有行数接口时执行来源侧数量核对。
12. 相同范围重复执行不产生重复记录。
13. 平台当前数据能够通过HIS只读视图读取。
14. 来源数、平台数和HIS读取数在相同范围内一致，差异均有业务解释。
